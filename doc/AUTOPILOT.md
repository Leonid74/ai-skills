# Профиль автопилота

## Санкция
- мёрж PR: да
- релиз: да
- staging: нет

Мёрж — `gh pr merge <N> --squash --match-head-commit <SHA>` из корня репозитория, без `--delete-branch` и `--admin`.
Релиз — версия в манифесте (`plugins/*/.claude-plugin/plugin.json`; `CLAUDE.md` §«Версионирование плагинов»): мёрж
PR с бампом и есть релиз, отдельного действия нет. Тегами проект не выпускается (`archive/…` — архивные метки).
Staging и автодеплоя в проекте нет. Обновление плагина на машине владельца после мёржа (`claude plugin marketplace
update`, `claude plugin update`) — правка вне репозитория: в санкцию не входит, его делает владелец командой `!`.

## Стоп-точки
- стоп-точки глобального `~/.claude/CLAUDE.md` и проектного `CLAUDE.md`;
- проход ревью 3 и дальше — только по согласованию владельца: варианты и оценка до запуска;
- правка дословно согласованного владельцем текста — на его одобрение до мёржа;
- `plugins/chat-handoff/skills/chat-handoff/SKILL.md` — vendor-копия, напрямую не править (`CLAUDE.md`
  §«Синхронизация vendor-копии chat-handoff»);
- удаление ветки после мёржа — только по слову владельца.

## Флоу
Ветка → реализация (при пользователь-видимом изменении плагина — бамп `version` и запись в `CHANGELOG.md`, `CLAUDE.md`
§«Версионирование плагинов») → проверки → ревью скиллом `review-code` → правки → PR (`/dev-toolkit:cppr`, метаданные
ревью — файлом) → мёрж. Задача — пункт `TODO.md` — по скиллу `todo-ship`. Уровень ревью — названный владельцем, иначе
по таблице `plugins/dev-toolkit/skills/review-code/SKILL.md` §«Таблица уровней» с учётом действующих глобальных
исключений (мораторий уровня `max`). Отдельного файла правил ревью (`doc/REVIEW.md`) в проекте нет.

## Чисто
Условия ниже — в дополнение к минимуму «чисто» скилла `autopilot` (он действует всегда).

- все подтверждённые (`CONFIRMED`) находки исправлены, закрытие каждой проверено по месту правки, и это уложилось в
  число проходов по правилам: не более 3 раундов правок ревью, проход 3 и дальше — только по согласованию (раздел
  «Стоп-точки»); неисправленная находка после этого — стоп с вопросом;
- ветка не правит дословно согласованный владельцем текст;
- при пользователь-видимом изменении плагина — бамп `version` в его `plugin.json` и запись в `CHANGELOG.md`.

## Проверки
Полная локальная проверка — все команды `CLAUDE.md` §«Валидация (нет автотестов — это и есть проверка перед
коммитом)», в обёртках `ulimit`/`timeout` из того же раздела. CI в проекте нет: засчитываются локальные проверки,
и это называется в итоге. Команды итога CI нет.

## Состояние
Действует в любом режиме — с автопилотом и без. Правила записи (PLAN, HANDOFF, список «СТАРТ» и его строка в
MEMORY.md, когда сохранять, завершение задачи) — шаги 4–6 скилла `autopilot` (файл `skills/autopilot/SKILL.md`
установленного плагина dev-toolkit): обычная сессия читает их перед первым сохранением. Этот раздел, как весь
профиль, читается из базовой ветки (шаг 1 скилла), а не из рабочего дерева.

- журнал ревью отдельно не ведётся — метаданные ревью идут в тело PR;
- HANDOFF — `.dev/HANDOFF-<тема>.md`, у каждой задачи свой;
- список «СТАРТ» — `autopilot-start.md` в памяти проекта (`~/.claude/projects/<проект>/memory/`), его строка — первой
  в `MEMORY.md` того же каталога;
- интервал лёгкого сохранения — 30 минут.

## Ловушки
- классификатор режима auto отклоняет `gh pr merge` без прямого слова владельца в сессии (PR #72, #76) и с
  `--delete-branch` при любом раскладе (PR #96): не обходить — номер PR и команда
  `! gh pr merge <N> --squash --match-head-commit <SHA>` владельцу;
- две сессии в одной папке делят ветку: перед `pull`/`commit`/`merge` — `git rev-parse --abbrev-ref HEAD`;
  одна сессия на проект — задача в ветке основного чекаута, не в отдельном worktree (в сессии из каталога worktree нет
  `.claude/settings.local.json` и `.dev/`; скилл `autopilot`, режим `init`);
- хук `guard-bash` судит текст команд: файлы состояния — инструментами Write/Edit, сообщение коммита и тело PR —
  файлом (`git commit -F`, `gh pr create --body-file`);
- удаление ветки после squash-мёржа: сначала `git branch -d` (пока жива удалённая), затем удалённая;
- живой tmux не трогать, опытные прогоны — под потолком памяти и времени (`CLAUDE.md` §«Валидация (нет
  автотестов — это и есть проверка перед коммитом)»).
