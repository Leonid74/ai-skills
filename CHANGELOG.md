# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Версии — отдельно по
каждому плагину маркетплейса (своя версия в `plugins/<plugin>/.claude-plugin/plugin.json`), плюс
отдельный раздел для изменений самого репозитория-маркетплейса, у которого нет собственной версии.

## dev-toolkit

### [1.17.0] — 2026-08-24

- Новый skill `todo-ship` — сквозное закрытие пункта списка задач: реализация в отдельной ветке,
  многоугловое ревью, правки со сверкой всех затронутых файлов, PR и проверки проекта, мёрж, релиз,
  проверка результата у потребителя, отметка в `TODO.md` и обновление памяти.
- Skill сознательно сделан **оркестратором**, а не самостоятельным движком: ревью делегируется
  `review-code`, PR — `/dev-toolkit:cppr`. Причина: два движка поиска багов в одном репозитории
  неизбежно разъезжаются. Следствие того же принципа — состав углов, уровни и потолки находок в
  тексте скилла **не воспроизводятся** (иначе перекалибровка таблицы `review-code` оставила бы в
  `todo-ship` ложную гарантию, которую не поймает ни одна проверка репозитория).
- Предохранители, заложенные в тело скилла (каждый — закрытая находка самоаудита, прогон
  `review-code` уровня `max` на собственном диффе: 9 углов + 3 верификационные линзы, 19 CONFIRMED):
  - **две раздельные санкции** вместо одной: на мёрж (шаг 1) и на выдачу результата потребителю
    (шаг 6.0). Склеенный вопрос «пункт 3, и мержим?» превращал односложное «да» в разрешение на
    необратимый деплой; цитаты обоих ответов — обязательные строки отчёта. Вторая санкция берётся
    **перед тем действием, которое выпускает изменение наружу**: перед тегом или деплоем, а при
    манифестном механизме (релиз наступает самим мёржем) — до мёржа, иначе вопрос задавался бы
    тогда, когда отменять уже нечего;
  - **порядок «всё в PR»**: бамп `version`, `CHANGELOG` и отметка пункта коммитятся в ветку до
    мёржа. Прежняя редакция ставила их после мёржа — то есть в состояние, где ветки уже нет, а
    прямой коммит в базовую запрещён глобальным правилом;
  - **шаг 8 гейтится фактическим исходом** шагов 6–7: при провалившемся релизе пункт не
    отмечается закрытым и в память не пишется «актуальная версия» — иначе ложный факт переживает
    сессию;
  - **ревью на шаге 3 запускается без target**: реализация ещё не закоммичена, и явный
    `<base>...HEAD` дал бы пустой дифф — ревью, не увидевшее ни строки. Явный target нужен на
    повторном прогоне, после пуша;
  - **уровень ревью не передаётся аргументом** (кроме `max` при касании security-поверхности или
    контрактов): переданный уровень отключает калибровку `review-code` по таблице;
  - **три исхода вместо двух** там, где неопределённость раньше трактовалась в пользу продолжения:
    `gh pr checks` различает «прошли» / «выполняются» (exit 8) / «чеки не зарегистрированы» (exit 1,
    типично в первые секунды после пуша) — последние два больше не читаются как «CI нет»; проверка
    прода различает «получено» / «старое значение из кэша CDN» (`raw.githubusercontent.com` кэширует
    до 5 минут — повторить, а не «чинить» повторным бампом) / «ответа нет вовсе»;
  - **проверяется потребительский путь**, а не сырой файл в репозитории: для плагина Claude Code
    это `/plugin marketplace update` и установленная у пользователя версия;
  - **открытая `CONFIRMED`-находка в объёме пункта блокирует мёрж**; цикл «правки → ревью»
    ограничен 3 раундами (поздние раунды наслаивают заплатки — вывод, зафиксированный при остановке
    самоаудита на 1.15.0), а незакрытые находки перечисляются в отчёте, а не сворачиваются в число;
  - **делегаты описаны точно**: `/dev-toolkit:pr` из шага 5 убран (он не коммитит и не пушит — в его
    `allowed-tools` нет `git add/commit/push`), а финальная фраза `cppr` «не делай ничего другого»
    явно объявлена ограничением её собственного хода, иначе конвейер молча заканчивался на PR;
  - **память не дедуплицируется против `CLAUDE.md`** — прежняя редакция предписывала обратное и
    противоречила `optimize-project-docs`, где перекрытие названо намеренным.
- Безопасность `allowed-tools`: из набора убраны `Bash(gh pr checks:*)` и `Bash(gh run list:*)` —
  префикс авто-одобряет команду целиком, а механический барьер `guard-bash.sh` доходит до leaf
  только у `gh pr diff/view`, так что `gh pr checks --web` (браузер) и `gh run list -R other/repo`
  (чужой репозиторий) прошли бы без промпта и без блокировки (проверено прогоном хука). Тем самым
  сохранён инвариант, зафиксированный в `TODO.md` при 1.16.0: множество auto-approved префиксов не
  выходит за пределы барьера. Также убраны осиротевшие `Agent` и `ReportFindings` (тело скилла их не
  вызывает — тот же класс, что чинился в 1.14.0), и добавлен текстовый инвариант «git/gh — только
  чтение», которого у `todo-ship`, в отличие от `review-code`, не было.
- Документация: `README` (список скиллов, секция `todo-ship`, дерево структуры, строка про
  обновление), `CLAUDE.md` (дерево структуры), `marketplace.json` (description синхронно с
  `plugin.json`, keywords `todo`/`release`/`workflow`).

### [1.16.0] — 2026-07-20

- Hook `guard-bash.sh`: **механический барьер для read-only git/gh** — закрыт отложенный пункт TODO
  (настоящий фикс security-находки третьего самоаудита review-code, инвариант 3 которого был лишь
  инструкцией модели). Новое правило внутри существующего разбора по сегментам (`&&`/`||`/`;`/`|`):
  - у `git diff/log/blame/show` блокируются `--output`/`-o`, `--ext-diff`, `--no-index`, `--exec` —
    подфлаги, превращающие формально read-only команду в запись файла, чтение вне репозитория или
    запуск внешней программы; long-опции матчатся по **префиксу**, потому что git принимает
    однозначные сокращения (`--outp=` == `--output=`);
  - у `gh pr diff/view` блокируются `--web`/`-w`, `-R`/`--repo`, `--exec` (браузер / чужой
    репозиторий) — точным совпадением (cobra сокращений не принимает) + эвристика на кластеры
    коротких флагов (`-cw`);
  - флаг-сеты git и gh **раздельные** (`-w` у git — легитимный ignore-all-space), скан флагов
    останавливается на `--` (дальше — пути), scope осознанно ограничен ровно auto-approved
    префиксами `allowed-tools` скилла review-code — глобальная блокировка `gh … -R`/`--web` ломала
    бы легитимные `gh pr list -R owner/repo` и `gh repo view --web` (детали и принятые ограничения —
    в `TODO.md`).
- Тесты: первый набор тест-векторов в репозитории — `hooks/tests/test-guard-bash.sh` (44 вектора:
  новое правило + регрессия `rm`/`git reset`/`git push -f`/`git branch -D`/`.env`).
- Skill `review-code`: примечание инварианта 3 обновлено — барьер существует с dev-toolkit ≥ 1.16.0,
  инструкция остаётся защитой для сред без хука плагина.

### [1.15.0] — 2026-07-20

- Skill `review-code`: закрыты CONFIRMED-находки третьего самоаудита (прогон 1.14.0 уровня `max` на
  диффе PR #38 — 15 находок в отчёте). Тактика этого раунда — **упрощать, а не наслаивать**: часть
  находок 1.14.0 были регрессиями, внесёнными точечными заплатками предыдущих версий.
  - **security**: новый сквозной инвариант 3 «git/gh — только чтение» — явный запрет подфлагов,
    которые префикс `allowed-tools` не блокирует (`--output`/`-o`, `--ext-diff`, `--no-index`,
    `--web`, `-R`, `--exec`); эмпирически `git diff --output=` писал файл, `--no-index` читал вне
    репо. Настоящий барьер — на уровне `guard-bash.sh` (в TODO);
  - **санитизация target**: «регэксп в уме» заменён детерминированной пошаговой проверкой; поддержка
    двухточечного `..` **убрана** (порождала молчаливую подмену семантики) — только трёхточечный
    диапазон; проверка ведущего `-` теперь на **каждую** сторону `<base>`/`<head>`, а не на строку
    целиком (закрыт two-arg-обход `HEAD...--ext-diff`); множественные/лишние dot-группы (`a....b`,
    `a...b...c`) отвергаются; диапазон собирается в один аргумент;
  - **scope**: `git diff HEAD~1 HEAD` вместо `git diff HEAD~1` (сравнивал с рабочим деревом →
    незакоммиченное дважды, закоммиченное могло выпасть); ступень `HEAD~1` срабатывает только когда
    текущая ветка **сама** базовая — на свежей ветке пустой range больше не затягивает чужой
    смерженный коммит; исход «ошибка команды» отделён от «пустой дифф» (реальный сбой поднимается, а
    не маскируется под «scope пуст» — обратная сторона фикса 1.14.0), частичный отказ каскада
    помечается в выводе;
  - **отказоустойчивость**: отказ finder-угла (упал / вернул прозу) — перезапуск, затем явная
    пометка непокрытого ракурса в сводке, чтобы «N углов» не выглядело полным покрытием;
  - **исправление своей опечатки**: тире-перечисление в разделе `low` (внесено в 1.14.0) сломало
    список — «дубль хелпера» и «мёртвый код» читались как приложение к «снятому guard'у»; переписано
    явными пунктами.
- Осознанно **не** трогалось (во избежание новых регрессий): PLAUSIBLE-находки (расщепление угла 2
  только на `max`, дубли санитизации, идентичные ячейки `xhigh`/`max`, README/план-дрейф,
  формулировка гейта самосогласия). Уровень зрелости скилла признан достаточным — дальнейшее латание
  доков на естественном языке даёт убывающую отдачу при риске новых заплаток-регрессий.

### [1.12.0] — 2026-07-20

- Skill `review-code` доработан по итогам сравнения со встроенным inline-`/code-review`
  (механизмы перенесены своими словами, вербатим-копирование промптов Anthropic по-прежнему
  запрещено — обоснование в `doc/plans/review-code-skill.md`, дополнение 2026-07-20):
  - углы поиска развёрнуты из ярлыков тем в «охотничьи» инструкции с каталогами классов багов:
    построчный проход с чтением объемлющей функции, аудит удалённых/заменённых строк
    (восстановлен ли инвариант), трассировка call-sites и callees, корректность обёрток/прокси,
    ловушки языка по стеку проекта (PHP/Go/JS/SQL);
  - новый угол «чистота и переиспользование» (reuse существующих хелперов, simplification,
    efficiency, altitude) — раньше reuse не искался вовсе;
  - верификация разделена по режимам: `medium` — скептик (precision); `high`/`xhigh` —
    трёхзначный вердикт, `PLAUSIBLE` по умолчанию, `REFUTED` только конструктивный с цитатой
    (реалистичные состояния — гонки, редкие error-path, штормы ретраев — опровергать нельзя);
    `max` — 3 разные линзы на локацию, убивает только ≥2 конструктивных `REFUTED`;
  - дедуп кандидатов **до** верификации и группировка верификаторов по локации (файл:строка) —
    кратное сокращение агентов без потери кандидатов;
  - анти-самоцензура finder'ов (каждый кандидат с называемым сценарием отказа идёт на
    верификацию), потолки кандидатов на угол (6–8) и находок на уровень (4/8/10/15/15),
    при обрезке корректность вытесняет чистоту;
  - `low` стал безагентным: один проход в текущем контексте, hunk-only, тестовые файлы
    пропускаются — раньше на дифф в 10 строк жглось 3+ агента;
  - дефолтный scope объединяет range-дифф (`@{upstream}...HEAD` с fallback'ами) **и**
    `git diff HEAD` — раньше «или/или» теряло закоммиченное при грязном рабочем дереве;
  - sweep-фаза на `xhigh`/`max`: свежий finder ищет только пропуски первого прохода;
  - `failure_scenario` — последствие для пользователя, а не промежуточное состояние; пути в
    находках нормализуются к repo-relative; fallback-режим без `Agent` с явным дисклеймером;
