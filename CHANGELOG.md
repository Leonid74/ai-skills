# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Версии — отдельно по
каждому плагину маркетплейса (своя версия в `plugins/<plugin>/.claude-plugin/plugin.json`), плюс
отдельный раздел для изменений самого репозитория-маркетплейса, у которого нет собственной версии.

## dev-toolkit

### [1.9.0] — 2026-07-17

- `/cppr` и `/pr`: при рассогласовании CLAUDE.md/README/CHANGELOG с изменениями команды теперь
  **перечисляют** найденные рассогласования, а не правят доки молча — правки на этом шаге обходили
  ревью, уже проведённое вызывающим флоу по текущему диффу.
- `/cppr` и `/pr`: если проверки (тесты/линтер) уже прогнаны в текущей сессии и дифф не менялся —
  повторно не гоняются (ссылка на полученный зелёный результат); при сомнении — прогон как раньше.
- `/cppr` и `/pr`: после создания PR печатается напоминание, что дефолтный scope локального
  `/code-review` после пуша ветки с upstream пуст — повторное ревью требует явный target.
- Почему: совместимость с флоу вызывающих проектов «ревью → сверка → фиксы → /cppr → мёрж»,
  где ревью — обязательный шаг ДО коммита/пуша.

### [1.8.2] — 2026-06-22

- Исправлено: детект рекурсивного `rm` в `guard-bash.sh` ловил флаг (`-r`/`-rf`) только если он
  был первым токеном сразу после `rm` — `rm -v -r file` проходил незаблокированным. Длинная форма
  `rm --recursive` не детектировалась вовсе.
- Детект переписан на токенизацию по словам: recursive-флаг ловится в любой позиции аргументов
  (в т.ч. после операнда, `rm /home/x -r`) и в короткой, и в длинной форме; восстановлена блокировка
  `rm -rf` без явного операнда в тексте команды (`find . | xargs rm -rf`).
- Исправлен попутно найденный на ревью баг: операнд сравнивался с `/tmp` без учёта регистра, из-за
  чего `rm -rf /TMP/x` проходил как разрешённый, хотя на Linux это не та же директория.
- Добавлен `CLAUDE.md` для репозитория, обновлены `README.md` (описание правила `rm`) и `TODO.md`
  (зафиксированы новые осознанные ограничения: сокращённые long-опции `rm`, пробел в пути при
  word-splitting).

## chat-handoff

### [1.3.0] — 2026-07-18

- Синхронизация vendor-копии с upstream 1.3.0: специфицирован расширенный режим; секреты (токены,
  ключи, webhook-URL) заменяются плейсхолдерами `<секрет: …>`; развилка «резюме vs handoff» для
  «суммаризируй чат» без new-chat intent; сверка «Текущего состояния» с `git status` в средах
  с инструментами; честная деградация при авто-компакции; правило целостности fence (четыре бэктика
  при сниппетах); каркас блока на языке чата; примеры сокращены с 3 до 2.
