# Настройка statusline

## Что делает этот skill

Настраивает строку статуса Claude Code, которая показывает: `user@host:папка | модель ◔ effort | Context NN% | 5h NN% | 7d NN% | git-ветка`.

Сегмент `Context` — процент заполнения контекстного окна (`context_window.used_percentage` из JSON сессии): до 59% без цвета, 60–79% жёлтый, от 80% красный. До первого ответа API поля нет — тогда сегмент не выводится.

Сегменты `5h` и `7d` — сколько **израсходовано** лимита подписки в пятичасовом окне и за неделю (`rate_limits.five_hour.used_percentage` и `rate_limits.seven_day.used_percentage`; остаток — 100 минус значение), пороги цвета те же. Блок `rate_limits` есть только при подписке claude.ai (Pro/Max) и появляется после первого ответа API; при работе по API-ключу его нет, а каждое из окон может отсутствовать по отдельности — сегмент без значения не выводится.

После названия модели через `◔` идёт уровень effort (`effort.level`: `low`…`max`, меняется вместе с `/effort`). Поля нет, если модель не поддерживает effort, — тогда выводится одно название модели.

Скрипт запускается по событиям сессии (новое сообщение ассистента, `/compact`, смена режима разрешений, наступление времени сброса окна лимита), в простое строка не обновляется. Чтобы она обновлялась и в простое, в секцию `statusLine` можно добавить `"refreshInterval": <секунды>` — по просьбе пользователя, сам скилл его не ставит.

Строка статуса — это bash-скрипт, получающий JSON сессии на stdin и выводящий форматированную строку. Claude Code вызывает его и показывает результат в интерфейсе.

### Мост в tmux: опция панели `@claude_ctx`

Если Claude Code запущен внутри tmux, скрипт дополнительно кладёт тот же процент в пользовательскую опцию панели `@claude_ctx` (целое число без знака `%`; значения нет — опция снята). Сам tmux процент контекста узнать не может, а из опции его читает строка статуса tmux — например, чтобы видеть заполнение контекста с узкого экрана телефона. Вне tmux мост ничего не делает; вывод скрипта от моста не зависит.

Что мост делает и чего требует — в комментарии шаблона (шаг 2). Строку статуса tmux скилл **не настраивает**: `~/.tmux.conf` — файл пользователя. Скилл проверяет условия работы моста (шаг 0) и сообщает пользователю, как прочитать опцию (шаг 4); полная справка — в README плагина, раздел `statusline-setup`.

## Шаги

### 0. Проверь зависимости

Убедись, что `jq` установлен:

```bash
jq --version
```

Если `jq` не найден — сообщи пользователю и остановись: без него скрипт завершается с ошибкой и строка статуса пуста. Для установки:
- Ubuntu/Debian: `sudo apt install jq`
- macOS: `brew install jq`

**Только если сессия идёт внутри tmux** (задана переменная `TMUX`) — проверь условия моста в tmux. Это предупреждения, а не остановка: без них строка статуса Claude Code работает, не работает только мост.

```bash
[ -n "${TMUX:-}" ] && { command -v timeout || echo "timeout: нет"; tmux -V; }
```

- `timeout` не найден — мост работать не будет. Нужен `timeout` с ключом `-s` (GNU coreutils; BusyBox от 1.30). macOS: `brew install coreutils`.
- tmux старше 3.0 — мост работать не будет (опции панели появились в 3.0).

Запомни результат — он нужен в шаге 4.

### 1. Проверь текущее состояние

Прочитай `~/.claude/settings.json` и найди секцию `statusLine`.

**Если `statusLine` уже настроен:**
- Сообщи пользователю, что statusline уже настроен
- Покажи текущее значение `command`
- Если `command` указывает на скрипт этого skill — `~/.claude/statusline.sh` (в том числе абсолютным путём, например `/home/username/.claude/statusline.sh`): прочитай файл и покажи пользователю **полный** diff текущего скрипта с шаблоном из шага 2 (`diff -u ~/.claude/statusline.sh <файл с шаблоном>`), а не пересказ — так видны и собственные доработки пользователя, которые перезапись сотрёт. Спроси, перезаписать ли скрипт новым шаблоном. Согласен — перейди к шагу 2 (вопрос про перезапись там уже задан, повторять не нужно), после шага 2 сразу к шагу 4: шаг 3 пропусти, `settings.json` уже указывает на скрипт
- Если `command` указывает на что-то другое (свой скрипт, inline-команда) — спроси, заменить ли его строкой статуса этого skill. Согласен — шаги 2–4; в шаге 3 замени значение `command` в существующей секции `statusLine`, второй ключ `statusLine` не добавляй
- Если пользователь решил оставить как есть — завершай, ничего не меняй

**Если `statusLine` отсутствует** — переходи к шагу 2.

### 2. Создай скрипт

Сначала проверь, существует ли уже `~/.claude/statusline.sh`:
- Если файл **существует** — прочитай текущее содержимое, покажи пользователю и спроси, перезаписать или оставить. Только при явном согласии — записывай новый скрипт.
- Если файл **отсутствует** — создавай без вопросов.

Содержимое `~/.claude/statusline.sh`:

```bash
#!/usr/bin/env bash
# Строка статуса Claude Code:
#   user@host:папка | модель ◔ effort | Context NN% | 5h NN% | 7d NN% | git-ветка.
# Получает JSON сессии на stdin (поля .model / .effort / .workspace /
# .context_window / .rate_limits).

set -euo pipefail

input="$(cat)"

# Все поля — одним вызовом jq (скрипт вызывается несколько раз в секунду), по
# строке на поле; папка — последней: только в ней допустим перевод строки.
# - Проценты (контекст; лимиты подписки за пять часов и за неделю — сколько
#   израсходовано): округление в jq, а не в printf — под ru_RU printf '%.0f'
#   ждёт десятичную запятую и падает на "83.4". Поля нет (контекст — до первого
#   ответа API; лимиты — ещё и без подписки claude.ai, и каждое окно по
#   отдельности) — пустая строка, сегмент не выводится. Не число или вне 0–100 —
#   тоже пустая строка.
# - effort — только строчные латинские буквы (low…max): значение уходит в
#   терминал. Поля нет, если модель не поддерживает effort.
# - try: поле не того типа (rate_limits — строка) даёт пустое значение, а не
#   ошибку jq, которая под set -e погасила бы всю строку статуса.
parsed="$(printf '%s' "$input" | jq -r '
  def pct(f): ((try f catch null) | numbers | round | select(. >= 0 and . <= 100)) // "";
  def str(f): (try f catch null) | strings;
  pct(.context_window.used_percentage),
  pct(.rate_limits.five_hour.used_percentage),
  pct(.rate_limits.seven_day.used_percentage),
  ((str(.effort.level) | select(test("\\A[a-z]{1,12}\\z"))) // ""),
  ((str(.model.display_name) | gsub("[\\r\\n]"; " ")) // "?"),
  (str(.workspace.current_dir) // str(.cwd) // ".")
')"
ctx="" limit_5h="" limit_7d="" effort="" model=""
for field in ctx limit_5h limit_7d effort model; do
  printf -v "$field" '%s' "${parsed%%$'\n'*}"
  parsed="${parsed#*$'\n'}"
done
dir="$parsed"

# Мост в tmux: процент контекста кладём в опцию панели @claude_ctx, откуда его
# читает строка статуса tmux (сам tmux этого значения узнать не может). Значения
# нет — опцию снимаем, чтобы не показывать старое.
# - Сервер и панель берём из TMUX и TMUX_PANE, обе сверяем с шаблоном: TMUX —
#   «<путь сокета>,<pid сервера>,…», TMUX_PANE — %N. Без TMUX или с пустым путём
#   клиент ушёл бы серверу по умолчанию, в чужую панель с тем же номером.
# - pid сервера сверяет сам сервер (#{pid}): если на том же сокете уже другой
#   сервер (прежний перезапущен), панель %N там чужая — не пишем.
# - Пишем только при изменении, и сравнивает тоже сервер (if -F): любая запись
#   опции перерисовывает строку статуса у всех клиентов tmux и перезапускает её
#   скрипты, а этот скрипт вызывается несколько раз в секунду.
# - Запуск в фоне (&): зависший сервер tmux не должен задерживать строку
#   статуса — Claude Code отменяет скрипт, не успевший до следующего обновления.
# - timeout -s KILL: клиент, застрявший на зависшем сервере, обычный SIGTERM
#   может не обработать — без KILL такие процессы копились бы без предела.
# - Вывод tmux не читаем и отрезаем его от своих потоков (< > /dev/null): клиент
#   передаёт серверу свои дескрипторы, и канал строки статуса ждал бы сервер.
# - Процент попадает в текст команды tmux, поэтому только 1–3 цифры; иное
#   значение считаем отсутствующим.
# - Нет tmux или timeout (нужен timeout с ключом -s: GNU coreutils, BusyBox от
#   1.30) — мост молча не работает, строка статуса цела. Нужен tmux 3.0 и новее.
tmux_re='^/[^,]+,[0-9]+,'
ctx_re='^[0-9]{1,3}$'
if [[ "${TMUX:-}" =~ $tmux_re && "${TMUX_PANE:-}" =~ ^%[0-9]+$ ]]; then
  tmux_pid="${TMUX#*,}"
  tmux_pid="${tmux_pid%%,*}"
  if [[ "$ctx" =~ $ctx_re ]]; then
    tmux_cond="#{!=:#{@claude_ctx},$ctx}"
    tmux_cmd="set -p -t $TMUX_PANE @claude_ctx $ctx"
  else
    tmux_cond='#{!=:#{@claude_ctx},}'
    tmux_cmd="set -pu -t $TMUX_PANE @claude_ctx"
  fi
  timeout -s KILL 1 tmux if -F -t "$TMUX_PANE" \
    "#{?#{==:#{pid},$tmux_pid},$tmux_cond,0}" "$tmux_cmd" </dev/null >/dev/null 2>&1 &
fi

# Короткое имя папки (~ вместо домашнего каталога).
short_dir="${dir/#$HOME/\~}"

# Ветка git, если текущая папка внутри репозитория.
branch=""
if git -C "$dir" rev-parse --abbrev-ref HEAD >/dev/null 2>&1; then
  branch="$(git -C "$dir" rev-parse --abbrev-ref HEAD 2>/dev/null)"
fi

# ANSI-цвета как в PS1.
green=$'\033[01;32m'
blue=$'\033[01;34m'
yellow=$'\033[01;33m'
red=$'\033[01;31m'
reset=$'\033[00m'

# user@host:dir в стиле PS1.
printf '%s%s@%s%s:%s%s%s' "$green" "$(whoami)" "$(hostname -s)" "$reset" "$blue" "$short_dir" "$reset"

# Модель и через ◔ (U+25D4) уровень effort, если он есть.
printf ' | %s' "$model"
if [ -n "$effort" ]; then
  printf ' \xe2\x97\x94 %s' "$effort"
fi

# pct_segment <подпись> <процент>: сегмент « | подпись NN%»; < 60% — без цвета,
# 60–79% — жёлтый, >= 80% — красный. Процент пуст — сегмент не выводится.
pct_segment() {
  local color=""
  [ -n "$2" ] || return 0
  if [ "$2" -ge 80 ]; then
    color="$red"
  elif [ "$2" -ge 60 ]; then
    color="$yellow"
  fi
  if [ -n "$color" ]; then
    printf ' | %s%s %s%%%s' "$color" "$1" "$2" "$reset"
  else
    printf ' | %s %s%%' "$1" "$2"
  fi
}

# Контекст и лимиты подписки: пятичасовое окно и неделя.
pct_segment Context "$ctx"
pct_segment 5h "$limit_5h"
pct_segment 7d "$limit_7d"

# Git-ветка (со значком Powerline ), если есть.
if [ -n "$branch" ]; then
  printf ' | \xee\x82\xa0 %s' "$branch"
fi
```

После создания файла сделай его исполняемым — выполни через Bash:

```bash
chmod +x ~/.claude/statusline.sh
```

### 3. Пропиши конфиг в settings.json

Перед редактированием прочитай `~/.claude/settings.json` и убедись, что текущий JSON валиден.

Добавь секцию `statusLine` — поведение зависит от состояния файла:

**Файл отсутствует** — создай с минимальным содержимым:
```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh"
  }
}
```

**Файл существует и равен `{}`** — запиши:
```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh"
  }
}
```

**Файл существует с другими ключами** — используй Edit для точечного добавления рядом с существующими ключами. Не перезаписывай весь файл.

**Секция `statusLine` уже есть** (пользователь согласился заменить свою команду в шаге 1) — замени Edit'ом только значение `command`; второй ключ `statusLine` не добавляй — дубль ключа ломает JSON.

> Если строка статуса не появляется после настройки, замени `~` на абсолютный путь, например `/home/username/.claude/statusline.sh` — некоторые окружения не раскрывают `~` без shell.

### 4. Подтверди результат

После настройки:
- Сообщи пользователю, что statusline настроен
- Покажи итоговую конфигурацию
- Предупреди, что изменения вступят в силу после перезапуска Claude Code (если сессия уже активна)
- **Если сессия идёт внутри tmux** — расскажи про мост: скрипт пишет процент контекста в опцию панели `@claude_ctx`, и её можно показать в строке статуса tmux. Покажи пример ниже и скажи, что это правка `~/.tmux.conf`, которую пользователь делает сам (после неё — `tmux source-file ~/.tmux.conf`); сам `~/.tmux.conf` не меняй без прямой просьбы. Если в шаге 0 не нашёлся `timeout` или tmux старше 3.0 — скажи, что мост работать не будет, и почему.

  Сегмент ставится **в начало** собственного `status-right` пользователя (здесь после сегмента — штатное значение tmux); длину поднять, иначе штатные 40 знаков обрежут строку:

  ```tmux
  set -g status-right-length 60
  set -g status-right '#{?#{m/r:^[0-9][0-9]?[0-9]?$,#{@claude_ctx}},CTX #{@claude_ctx}%% | ,}"#{=21:pane_title}" %H:%M %d-%b-%y'
  ```

  Ограничения, о которых стоит сказать: значение проверяется самим форматом (`#{m/r:…}` — 1–3 цифры) и без такой проверки его нельзя подставлять в команду внутри `#(…)`; опцию `@claude_ctx` нельзя задавать выше панели (`set -g`/`-w`/`-s`); после выхода из Claude старое число остаётся в панели, пока в ней снова не запустят Claude. Подробности — README плагина.

Затем автоматически проверь наличие Nerd Font / Powerline-шрифта — выполни через Bash:

```bash
fc-list 2>/dev/null | grep -iE "nerd|powerline|MesloLGS|FiraCode Nerd|JetBrainsMono Nerd|Hack Nerd"
```

**Если вывод непустой** (шрифт найден) — сообщи пользователю, что Nerd Font обнаружен, значок ветки должен отображаться корректно. На этом всё.

**Если вывод пустой** (шрифт не найден) — предупреди:

> «Nerd Font / Powerline-совместимый шрифт не обнаружен — значок ветки  может отображаться как □. Выберите вариант:
> 1. Установить Nerd Font автоматически.
> 2. Убрать значок из скрипта.»

Дождись выбора и выполни:

- **Вариант 1 — установить автоматически:**
  Определи ОС и доступный пакетный менеджер:
  - Linux + `apt`: `sudo apt install fonts-powerline`
  - Linux + `dnf`: `sudo dnf install powerline-fonts`
  - Linux + `pacman`: `sudo pacman -S powerline-fonts`
  - macOS + `brew`: `brew install --cask font-hack-nerd-font`

  Если подходящий менеджер найден — выполни установку.
  Если ни один не доступен — установить автоматически нельзя; напиши пользователю:
  > «Установите шрифт вручную: https://www.nerdfonts.com/font-downloads — скачайте любой шрифт, распакуйте, установите через менеджер шрифтов системы.»

  В любом случае (и при успешной автоустановке, и при ручной инструкции) напомни:
  > «После установки выберите этот шрифт в настройках вашего терминала и перезапустите его — без этого шага значок не появится.»

- **Вариант 2 — убрать значок:**
  Отредактируй `~/.claude/statusline.sh` — замени строку:
  ```
  printf ' | \xee\x82\xa0 %s' "$branch"
  ```
  на:
  ```
  printf ' | %s' "$branch"
  ```

## Важно

- Никогда не удаляй существующий `~/.claude/statusline.sh` без явного разрешения пользователя — предложи сначала показать текущее содержимое
- `settings.json` — это JSON без комментариев; некорректное редактирование (незакрытая скобка, лишняя запятая) сломает конфигурацию — всегда проверяй валидность перед правками
- Значок ветки `` требует Nerd Font / Powerline-совместимого шрифта в терминале; если отображается `□` — уберите `\xee\x82\xa0` из скрипта
