# Настройка statusline

## Что делает этот skill

Настраивает строку статуса Claude Code, которая показывает: `user@host:папка | модель ◔ effort | Context NN% | 5h NN% (resets in 2h29m) | 7d NN% | cache warm 31m | git-ветка`.

Сегмент `Context` — процент заполнения контекстного окна (`context_window.used_percentage` из JSON сессии): до 59% без цвета, 60–79% жёлтый, от 80% красный. До первого ответа API поля нет — тогда сегмент не выводится.

Сегменты `5h` и `7d` — сколько **израсходовано** лимита подписки в пятичасовом окне и за неделю (`rate_limits.five_hour.used_percentage` и `rate_limits.seven_day.used_percentage`; остаток — 100 минус значение), пороги цвета те же — с одним отличием: когда выведен темп (следующий абзац), сегмент жёлтый и ниже 60%. Блок `rate_limits` есть только при подписке claude.ai (Pro/Max) и появляется после первого ответа API; при работе по API-ключу его нет, а каждое из окон может отсутствовать по отдельности — сегмент без значения не выводится. Когда наступает время сброса окна, Claude Code убирает его из JSON — сегмент пропадает до следующего ответа API, а не обнуляется.

У `5h` после процента идёт отсчёт до сброса окна — `(resets in 2h29m)`, `(resets in 29m)`, `(resets in <1m)` — из `rate_limits.five_hour.resets_at`; у недели отсчёта нет. У обоих окон перед отсчётом может стоять темп — `5h 53% 4.0× (resets in 4h20m)`: во сколько раз расход с начала окна быстрее ровного, при котором лимит кончается точно к сбросу. Темп выводится только от `1.0×` (при таком расходе лимит кончится раньше сброса) и не раньше 5% окна, с округлением до десятых, а от `10×` — целым числом; с темпом сегмент жёлтый, от 80% — красный, отсчёт всегда без цвета.

Сегмент `cache` — состояние кэша промпта основной переписки (`prompt_cache`, Claude Code 2.1.251 и новее; до первого ответа API и в старых версиях сегмента нет):

- `cache warm 31m` — кэш тёплый, столько осталось до истечения; следующее сообщение читает контекст из кэша дёшево. Жёлтый — в последней шестой части срока жизни (10 минут из часа, но не меньше минуты). `(5m ttl)` — действует пятиминутный срок вместо часового.
- `cache cold · 151k` — кэш остыл: следующее сообщение заново обработает около 151 тыс. токенов по полной цене. Без числа — когда объём неизвестен.
- Холодным показывается и кэш с ещё не истёкшим сроком, который следующий запрос не прочтёт: после `/compact` и очистки старых результатов инструментов (до следующего запроса) и когда сам Claude Code передаёт `warm: false`. После `/clear` и `/new` объекта `prompt_cache` в данных нет до первого ответа новой переписки — сегмента нет.
- **Смену модели сегмент не видит.** После `/model` Claude Code до первого ответа новой модели передаёт прежний «тёплый» кэш, хотя у новой модели кэш свой и следующее сообщение обработает всю историю заново. Об этом предупреждает сам диалог `/model`; после первого ответа новой модели сегмент снова точен.

Скрипт не создаёт и не читает файлов, транскрипты не читает, в сеть не ходит (внутри tmux он пишет опцию панели — см. «Мост в tmux»).

Папка, название модели, имя пользователя, хост и имя ветки выводятся очищенными: убираются управляющие символы и перечень невидимых знаков, меняющих вид строки, — смена направления письма, знаки нулевой ширины U+200B–U+200F и U+2060–U+206F, U+061C, U+FEFF, теги U+E0000–U+E007F. Перечень не исчерпывающий: прочие невидимые знаки юникода (мягкий перенос, вариационные селекторы) проходят, так что имя ветки в чужом репозитории может выглядеть не тем, чем является. Имя, хост или ветка, в которых такие знаки вложены друг в друга глубже семи уровней, не выводятся вовсе (пустое значение) — обычным именем это быть не может.

### Узкий экран: строка сжимается под ширину терминала

Claude Code передаёт скрипту ширину терминала в `COLUMNS`; видимых знаков у строки статуса на четыре меньше (поля), а строку длиннее он обрезает справа с `…` — первыми пропали бы ветка и кэш. Поэтому **на узком экране — уже 80 колонок, то есть на телефоне** — скрипт сам выбирает первую ступень, которая помещается. От 80 колонок (компьютер) строка всегда полная, даже если не помещается; порог — переменная `narrow_below` в конце скрипта.

| Ступень | Что выводится | Пример |
|---|---|---|
| полная | всё, как описано выше | `user@host:~/proj \| Opus 5.5 ◔ high \| Context 42% \| 5h 37% (resets in 2h29m) \| 7d 61% 1.2× \| cache warm 31m \|  main` |
| средняя | без `user@host`, effort и слов | `~/proj \| Opus 5.5 \| Ctx 42% \| 5h 37% 2h29m \| 7d 61% 1.2× \| cache 31m \|  main` |
| сжатая | без папки и модели | `Ctx 42% · 5h 37% 2h29m · 7d 61% 1.2× · cache 31m ·  main` |
| две строки | те же сегменты: контекст и лимиты / кэш и ветка | `Ctx 42% · 5h 37% 2h29m · 7d 61% 1.2×`<br>`cache 31m ·  main` |
| три строки | контекст и `5h` / `7d` / кэш и ветка | `Ctx 42% · 5h 37% 2h29m`<br>`7d 61% 1.2×`<br>`cache 31m ·  main` |

- Ступень подходит, когда помещается каждая её строка. Три строки — последняя ступень, она выводится без проверки: на самом узком экране (например, уже 44 колонок при остывшем кэше и ветке от 20 знаков) строка всё равно может оказаться длиннее, и её хвост обрежет Claude Code.
- У ветки есть короткий вид: без мягких переносов (а если имя и без них приходится укорачивать — и без вариационных селекторов), не длиннее 20 знаков (и 120 байт, не считая `…`; пример — `feat/statusline-nar…`; срез — по границе знака, комбинирующие знаки — буквы «й», «ё» в именах macOS — местом не считаются). Если он отличается от самой ветки, на средней и сжатой ступени и в двух строках он пробуется перед переходом к следующей ступени, а в трёх строках выводится всегда. В длине строки мягкий перенос считается знаком (терминалы рисуют его по-разному), вариационные селекторы и комбинирующие знаки — нет. Имя, которое после удаления невидимых знаков не удаётся очистить или от которого не остаётся ничего видимого, в коротком виде заменяется на `…`. Ветка длиннее 255 байт на узком экране выводится только в коротком виде — на любой ступени: объём вывода и счёт длины строки не растут с длиной чужого имени. Ограничения короткого вида: у имени длиннее 120 байт цепочка комбинирующих знаков может занять весь срез — тогда от имени видно только начало или одно `…`; подготовка короткого вида идёт по всему имени, и на bash 3.2 (macOS) имя в несколько килобайт стоит до секунд на обновление.
- После полной ступени: отсчёт — без слов (`2h29m`), тёплый кэш — `cache 31m`, остывший — `cache cold 151k`, пятиминутный срок — `(5m)`. Цвета те же.
- На сжатой ступени, в двух и в трёх строках, когда показать нечего (данных ещё нет, папка не в репозитории), выводится название модели; пустой строка статуса не бывает — при пустом вводе выводится полная.
- `COLUMNS` нет, это не число из 1–4 цифр или оно меньше 20 — полная строка, как до 2.10.0 и как от 80 колонок.
- При смене ширины окна (поворот телефона) скрипт заново не запускается: ступень сменится со следующим обновлением строки — событием сессии или по `refreshInterval`.
- Знак двойной ширины (иероглиф, эмодзи) в папке или ветке считается за один, байты вне UTF-8 в имени ветки не считаются вовсе: такая строка может оказаться длиннее экрана, и её обрежет Claude Code.
- Ширина считается как `COLUMNS − 4`. Настройку `padding` секции `statusLine` (дополнительный отступ) скрипт не видит, а уведомления Claude Code вне полноэкранного режима (ошибка MCP-сервера, автообновление, счётчик токенов в verbose-режиме) делят ряд со строкой статуса — в обоих случаях подобранная строка может быть обрезана справа.

Переменная окружения `NO_COLOR` (непустая) отключает цвета.

После названия модели через `◔` идёт уровень effort (`effort.level`: `low`…`max`, меняется вместе с `/effort`). Поля нет, если модель не поддерживает effort, — тогда выводится одно название модели.

Скрипт запускается по событиям сессии — среди них старт сессии, новое сообщение ассистента, `/compact`, смена режима разрешений, наступление времени сброса окна лимита, истечение тёплого кэша, — в простое строка не обновляется. Поэтому отсчёты (`resets in …`, `cache warm …`) в простое замирают; сама смена состояния — сброс окна, истечение кэша — перерисовывается без таймера. Чтобы строка обновлялась и в простое, в секцию `statusLine` добавляется `"refreshInterval": <секунды>` — скилл спрашивает об этом в шаге 4 и ставит только по согласию.

Строка статуса — это bash-скрипт, получающий JSON сессии на stdin и выводящий форматированную строку. Claude Code вызывает его и показывает результат в интерфейсе.

### Мост в tmux: опция панели `@claude_ctx`

Если Claude Code запущен внутри tmux, скрипт дополнительно кладёт тот же процент в пользовательскую опцию панели `@claude_ctx` (целое число без знака `%`; значения нет — опция снята). Сам tmux процент контекста узнать не может, а из опции его читает строка статуса tmux — например, чтобы видеть заполнение контекста с узкого экрана телефона. Вне tmux мост ничего не делает; вывод скрипта от моста не зависит.

Что мост делает и чего требует — в комментарии шаблона (шаг 2). Строку статуса tmux скилл **не настраивает**: `~/.tmux.conf` — файл пользователя. Скилл проверяет условия работы моста (шаг 0) и сообщает пользователю, как прочитать опцию (шаг 4); полная справка — в README плагина, раздел `statusline-setup`.

## Шаги

### 0. Проверь зависимости

Убедись, что `jq` установлен:

```bash
jq --version
```

Если `jq` не найден — сообщи пользователю и остановись: без него скрипт завершается с ошибкой и строка статуса пуста. Для установки:
- Ubuntu/Debian: `sudo apt install jq`
- macOS: `brew install jq`

**Только если сессия идёт внутри tmux** (задана переменная `TMUX`) — проверь условия моста в tmux. Это предупреждения, а не остановка: без них строка статуса Claude Code работает, не работает только мост.

```bash
[ -n "${TMUX:-}" ] && { command -v timeout || echo "timeout: нет"; tmux -V; }
```

- `timeout` не найден — мост работать не будет. Нужен `timeout` с ключом `-s` (GNU coreutils; BusyBox от 1.30). macOS: `brew install coreutils`.
- tmux старше 3.0 — мост работать не будет (опции панели появились в 3.0).

Запомни результат — он нужен в шаге 4.

### 1. Проверь текущее состояние

Прочитай `~/.claude/settings.json` и найди секцию `statusLine`.

**Если `statusLine` уже настроен:**
- Сообщи пользователю, что statusline уже настроен
- Покажи текущее значение `command`
- Если `command` указывает на скрипт этого skill — `~/.claude/statusline.sh` (в том числе абсолютным путём, например `/home/username/.claude/statusline.sh`): прочитай файл и покажи пользователю **полный** diff текущего скрипта с шаблоном из шага 2 (`diff -u ~/.claude/statusline.sh <файл с шаблоном>`), а не пересказ — так видны и собственные доработки пользователя, которые перезапись сотрёт. Спроси, перезаписать ли скрипт новым шаблоном. Согласен — перейди к шагу 2 (вопрос про перезапись там уже задан, повторять не нужно), после шага 2 сразу к шагу 4: шаг 3 пропусти, `settings.json` уже указывает на скрипт
- Если `command` указывает на что-то другое (свой скрипт, inline-команда) — спроси, заменить ли его строкой статуса этого skill. Согласен — шаги 2–4; в шаге 3 замени значение `command` в существующей секции `statusLine`, второй ключ `statusLine` не добавляй
- Если пользователь решил оставить как есть — завершай, ничего не меняй

**Если `statusLine` отсутствует** — переходи к шагу 2.

### 2. Создай скрипт

Сначала проверь, существует ли уже `~/.claude/statusline.sh`:
- Если файл **существует** — прочитай текущее содержимое, покажи пользователю и спроси, перезаписать или оставить. Только при явном согласии — записывай новый скрипт.
- Если файл **отсутствует** — создавай без вопросов.

Содержимое `~/.claude/statusline.sh`:

```bash
#!/usr/bin/env bash
# Строка статуса Claude Code:
#   user@host:папка | модель ◔ effort | Context NN% | 5h NN% (resets in 2h29m) |
#   7d NN% | cache warm 31m | git-ветка.
# На узком экране (уже 80 колонок) строка сжимается под ширину терминала
# (COLUMNS) — см. render, layout и narrow_below в конце файла.
# Получает JSON сессии на stdin (поля .model / .effort / .workspace /
# .context_window / .rate_limits / .prompt_cache). Файлов не пишет и не читает.
# Окружение: NO_COLOR (непустое) — без ANSI-цветов; COLUMNS — ширина терминала
# (задаёт Claude Code); STATUSLINE_NOW — текущее
# время в секундах эпохи вместо часов: только для тестов, в рабочем окружении
# не задавать — отсчёты и состояние кэша считались бы от застывшего времени.

set -euo pipefail

# Все поля — одним вызовом jq (скрипт вызывается несколько раз в секунду): по
# строке на поле, затем папка как есть (в пути допустим перевод строки) и
# строка-замок «.» — без неё $(…) срезал бы пустую или кончающуюся переводом
# строки папку, и поля сдвинулись бы.
# - one: ровно одна строка на поле — первое значение либо запасное, в том числе
#   когда поле не того типа (rate_limits — строка): ошибка jq под set -e
#   погасила бы всю строку статуса.
# - Проценты (контекст; лимиты подписки за пять часов и за неделю — сколько
#   израсходовано): округление в jq, а не в printf — под ru_RU printf '%.0f'
#   ждёт десятичную запятую и падает на "83.4". Поля нет (контекст — до первого
#   ответа API; лимиты — ещё и без подписки claude.ai, и каждое окно по
#   отдельности) — пустая строка, сегмент не выводится. Не число, отрицательное
#   или больше 999 — тоже пустая строка.
# - В терминал уходит только проверенное: effort — до 12 строчных латинских
#   букв (low…max), из названия модели и из показываемой папки убраны управляющие
#   символы и невидимые знаки, меняющие вид строки (shown; набор hidden — тот
#   же, что у функции clean ниже: менять только вместе), — иначе имя каталога
#   с escape-последовательностью, переводом строки или сменой направления
#   письма переписало бы строку статуса. Регулярки jq не нужны: сборка jq без
#   них не должна гасить строку.
# - Пустая строка в названии модели и в папке — как отсутствие поля; путь с
#   NUL-байтом (настоящим путём быть не может) — тоже. Название модели, от
#   которого после очистки ничего не осталось, — «?»; папка в том же случае
#   показывается пустой (git всё равно получает путь как есть). Поля effort
#   нет, если модель его не поддерживает.
# - Время сброса окна лимита (win) — только будущее и не дальше длины окна плюс
#   час; иначе ни отсчёта, ни темпа, процент остаётся. Отсчёт (dur) — «<1m»,
#   «29m», «2h29m», округление вниз.
# - Темп (pace) — расход относительно ровного, при котором окно кончается ровно
#   к сбросу: средний с начала окна (начало — время сброса минус длина окна).
#   Выводится от 1.0 (лимит кончится раньше сброса) и не раньше 5% окна — в
#   начале одна вспышка дала бы огромное число. Десятые собираются из целых:
#   tostring у дробного числа в старых jq даёт «3.8999999999999999».
# - Кэш промпта (.prompt_cache, Claude Code от 2.1.251) — всегда три строки
#   (нет данных — пустые): состояние (слово warm — в пределах TTL, soon —
#   последняя шестая часть TTL, но не меньше минуты, cold — остыл), текст
#   (остаток времени; у cold — сколько токенов перекэширует следующий запрос,
#   «151k») и «5m» для пятиминутного TTL. Остаток не больше самого TTL.
#   caching_observed: false (кэширование выключено или о нём не сообщают) —
#   сегмента нет, что бы ни стояло в остальных полях. expires_at нет: cold,
#   только если кэширование в сессии наблюдалось (caching_observed: true),
#   иначе сегмента нет. Транскрипт не читается, файлов
#   скрипт не пишет. Порядок веток важен: истёк либо warm: false (сам Claude
#   Code считает кэш не тёплым) → компакция → soon → warm. Компакция: после
#   /compact и очистки старых результатов инструментов Claude Code оставляет
#   кэш «тёплым», но recache_tokens_if_cold в объекте — null (поле есть,
#   значения нет): переписанный разговор ещё не кэширован — cold без объёма.
#   Смена модели не определяется: после /model Claude Code оставляет в данных
#   прежний «тёплый» кэш до первого ответа новой модели, и из одних этих
#   данных смену не увидеть (о перечитывании истории предупреждает сам диалог
#   /model).
# - Значения из JSON в строки отсчёта, темпа и кэша не попадают: состояние
#   кэша — одно из трёх слов-литералов, остальное собрано из цифр, букв
#   h/m/k, «<» и «.».
now_arg="${STATUSLINE_NOW:-}"
now_re='^[0-9]{1,12}$'
[[ "$now_arg" =~ $now_re ]] || now_arg=""
parsed="$(jq -r --arg t "$now_arg" '
  def one(f; d): ([f?] | .[0]) // d;
  def pct(f): one(f | numbers | select(. >= 0) | round | select(. <= 999) | . + 0; "");
  def str(f): f? | strings | select(. != "");
  def hidden: . == 1564 or (. >= 8203 and . <= 8207) or (. >= 8232 and . <= 8238)
    or (. >= 8288 and . <= 8303) or . == 65279 or (. >= 917504 and . <= 917631);
  def shown: explode | map(select((. >= 32 and . < 127) or (. > 159 and (hidden | not)))) | implode;
  def dur: floor | if . < 60 then "<1m" elif . < 3600 then "\(. / 60 | floor)m"
    else "\(. / 3600 | floor)h\(. % 3600 / 60 | floor | if . < 10 then "0\(.)" else "\(.)" end)m" end;
  ($t | if . == "" then now else tonumber end | floor) as $now
  | def win(f; $len): one(f | numbers | select(. > $now and . <= $now + $len + 3600) | floor; null);
    def pace(f; $r; $len): one(
      ($r | numbers | $now - (. - $len)) as $el
      | select($el >= $len * 0.05)
      | (f | numbers | select(. >= 0 and . <= 999)) * $len / $el / 10 | select(. >= 10) | round
      | if . >= 100 then "\(. / 10 | round)" else "\(. / 10 | floor).\(. % 10)" end; "");
    def cache: one(.prompt_cache | objects; null) as $pc
      | if $pc == null or $pc.caching_observed == false then ["", "", ""] else
          (if $pc.ttl == "5m" then [300, "5m"] else [3600, ""] end) as [$ttl, $tier]
          | ($pc.expires_at) as $e
          | ($pc.recache_tokens_if_cold | if type == "number" and . >= 1 and . < 1e9
              then (if . >= 1000 then "\(. / 1000 | round)k" else "\(floor)" end) else "" end) as $re
          | if ($e | type) == "number" and $e > 0 and $e < 1e12 then
              ([$e - $now, $ttl] | min | floor) as $left
              | if $left <= 0 or $pc.warm == false then ["cold", $re, ""]
                elif ($pc | has("recache_tokens_if_cold")) and $pc.recache_tokens_if_cold == null
                  then ["cold", "", ""]
                elif $left <= ([$ttl / 6, 60] | max) then ["soon", ($left | dur), $tier]
                else ["warm", ($left | dur), $tier] end
            elif $e == null and $pc.caching_observed == true then ["cold", $re, ""]
            else ["", "", ""] end
        end;
    win(.rate_limits.five_hour.resets_at; 18000) as $r5
  | win(.rate_limits.seven_day.resets_at; 604800) as $r7
  | pct(.context_window.used_percentage),
    pct(.rate_limits.five_hour.used_percentage),
    pct(.rate_limits.seven_day.used_percentage),
    ($r5 | if . == null then "" else . - $now | dur end),
    pace(.rate_limits.five_hour.used_percentage; $r5; 18000),
    pace(.rate_limits.seven_day.used_percentage; $r7; 604800),
    cache[],
    one(str(.effort.level) | select(length <= 12 and (explode | all(. >= 97 and . <= 122))); ""),
    one(str(.model.display_name) | shown | select(. != ""); "?"),
    (one(str(.workspace.current_dir), str(.cwd) | select(explode | index(0) | not); ".") | (shown, ., "."))
')"
ctx="" limit_5h="" limit_7d="" resets_5h="" pace_5h="" pace_7d=""
cache_kind="" cache_text="" cache_tier="" effort="" model="" dir_shown=""
for field in ctx limit_5h limit_7d resets_5h pace_5h pace_7d \
  cache_kind cache_text cache_tier effort model dir_shown; do
  printf -v "$field" '%s' "${parsed%%$'\n'*}"
  parsed="${parsed#*$'\n'}"
done
dir="${parsed%$'\n'.}"

# Мост в tmux: процент контекста кладём в опцию панели @claude_ctx, откуда его
# читает строка статуса tmux (сам tmux этого значения узнать не может). Значения
# нет — опцию снимаем, чтобы не показывать старое.
# - Сервер и панель берём из TMUX и TMUX_PANE, обе сверяем с шаблоном: TMUX —
#   «<путь сокета>,<pid сервера>,…», TMUX_PANE — %N. Без TMUX или с пустым путём
#   клиент ушёл бы серверу по умолчанию, в чужую панель с тем же номером.
# - pid сервера сверяет сам сервер (#{pid}): если на том же сокете уже другой
#   сервер (прежний перезапущен), панель %N там чужая — не пишем.
# - Пишем только при изменении, и сравнивает тоже сервер (if -F): любая запись
#   опции перерисовывает строку статуса у всех клиентов tmux и перезапускает её
#   скрипты, а этот скрипт вызывается несколько раз в секунду.
# - Запуск в фоне (&): зависший сервер tmux не должен задерживать строку
#   статуса — Claude Code отменяет скрипт, не успевший до следующего обновления.
# - timeout -s KILL: клиент, застрявший на зависшем сервере, обычный SIGTERM
#   может не обработать — без KILL такие процессы копились бы без предела.
# - Вывод tmux не читаем и отрезаем его от своих потоков (< > /dev/null): клиент
#   передаёт серверу свои дескрипторы, и канал строки статуса ждал бы сервер.
# - Процент попадает в текст команды tmux, поэтому только 1–3 цифры; иное
#   значение считаем отсутствующим.
# - Нет tmux или timeout (нужен timeout с ключом -s: GNU coreutils, BusyBox от
#   1.30) — мост молча не работает, строка статуса цела. Нужен tmux 3.0 и новее.
tmux_re='^/[^,]+,[0-9]+,'
ctx_re='^[0-9]{1,3}$'
if [[ "${TMUX:-}" =~ $tmux_re && "${TMUX_PANE:-}" =~ ^%[0-9]+$ ]]; then
  tmux_pid="${TMUX#*,}"
  tmux_pid="${tmux_pid%%,*}"
  if [[ "$ctx" =~ $ctx_re ]]; then
    tmux_cond="#{!=:#{@claude_ctx},$ctx}"
    tmux_cmd="set -p -t $TMUX_PANE @claude_ctx $ctx"
  else
    tmux_cond='#{!=:#{@claude_ctx},}'
    tmux_cmd="set -pu -t $TMUX_PANE @claude_ctx"
  fi
  timeout -s KILL 1 tmux if -F -t "$TMUX_PANE" \
    "#{?#{==:#{pid},$tmux_pid},$tmux_cond,0}" "$tmux_cmd" </dev/null >/dev/null 2>&1 &
fi

# Короткое имя папки (~ вместо домашнего каталога) — из очищенного пути.
short_dir="${dir_shown/#$HOME/\~}"

# clean <имя переменной>…: убрать из значений то, что переписало бы строку
# статуса или подменило бы её вид, — управляющие символы C0 и DEL, C1
# (U+0080–U+009F) и невидимые знаки: U+061C, U+200B–U+200F, U+2028–U+202E,
# U+2060–U+206F, U+FEFF, U+E0000–U+E007F (тот же набор, что hidden в jq выше:
# менять только вместе).
# - По байтам под LC_ALL=C: результат не зависит от локали пользователя (в
#   bash до 5.0 диапазоны в шаблонах иначе шли бы по порядку сортировки локали).
# - Проходы повторяются, пока значение меняется: иначе удаление одной
#   последовательности склеило бы из соседних байтов другую, уже пропущенную.
#   Проходов не больше восьми: значение, которое и после них меняется
#   (вложенность глубже семи уровней), обычным именем быть не может —
#   оно отбрасывается целиком. Без предела время росло бы с квадратом длины.
# - Набор не исчерпывающий: прочие невидимые знаки юникода (мягкий перенос
#   U+00AD, вариационные селекторы и другие) проходят. Управляющих
#   последовательностей терминала они не дают, но вид имени подменить могут.
# - Все переменные — одним вызовом: смена локали на входе и выходе функции
#   стоит заметного времени.
# - Граница: одиночный байт 0x80–0x9F вне корректной последовательности UTF-8
#   не убирается (в UTF-8-терминале он не управляющий; без разбора UTF-8 его
#   не отличить от хвоста обычной буквы).
clean() {
  local LC_ALL=C name value before passes
  for name in "$@"; do
    value="${!name}"
    before=""
    passes=0
    while [ "$value" != "$before" ]; do
      if [ "$passes" -ge 8 ]; then
        value=""
        break
      fi
      passes=$((passes + 1))
      before="$value"
      value="${value//[$'\001'-$'\037'$'\177']/}"
      value="${value//$'\302'[$'\200'-$'\237']/}"
      value="${value//$'\330\234'/}"
      value="${value//$'\342\200'[$'\213'-$'\217']/}"
      value="${value//$'\342\200'[$'\250'-$'\256']/}"
      value="${value//$'\342\201'[$'\240'-$'\257']/}"
      value="${value//$'\357\273\277'/}"
      value="${value//$'\363\240'[$'\200'$'\201'][$'\200'-$'\277']/}"
    done
    printf -v "$name" '%s' "$value"
  done
}

# Ветка git, если текущая папка внутри репозитория. Один вызов: при ошибке
# (не репозиторий; репозиторий без коммитов — там git печатает «HEAD» и
# завершается с ошибкой) ветки нет. Имя ветки приходит из репозитория, который
# мог быть чужим, — в терминал только очищенным (clean ниже, вместе с именем
# и хостом).
branch="$(git -C "$dir" rev-parse --abbrev-ref HEAD 2>/dev/null)" || branch=""

# ANSI-цвета как в PS1; NO_COLOR (непустое) — без цветов.
green="" blue="" yellow="" red="" reset=""
if [ -z "${NO_COLOR:-}" ]; then
  green=$'\033[01;32m'
  blue=$'\033[01;34m'
  yellow=$'\033[01;33m'
  red=$'\033[01;31m'
  reset=$'\033[00m'
fi

# user@host:dir в стиле PS1. Имя и хост — из переменных оболочки (HOSTNAME bash
# выставляет сам), без запуска процессов; whoami и hostname — только если
# переменная пуста, и их сбой (нет записи о пользователе, нет утилиты) даёт
# пустое имя, а не пустую строку статуса. Значения из окружения — в терминал
# только очищенными.
user="${USER:-}"
if [ -z "$user" ]; then
  user="$(whoami 2>/dev/null)" || user=""
fi
host="${HOSTNAME:-}"
if [ -z "$host" ]; then
  host="$(hostname -s 2>/dev/null)" || host=""
fi
host="${host%%.*}"
clean user host branch

# Знаки вне ASCII — байтами UTF-8: ◔ (U+25D4) перед effort, значок ветки
# Powerline (U+E0A0) с пробелом, × (U+00D7) у темпа, · (U+00B7) и … (U+2026).
effort_sep=$'\xe2\x97\x94'
branch_icon=$'\xee\x82\xa0 '
times=$'\xc3\x97'
dot=$'\xc2\xb7'
ellipsis=$'\xe2\x80\xa6'

# Строка собирается в out функцией render <ступень>. add, flush и pct_segment
# вызываются только из неё и работают с её локальными переменными: дописывают
# cur (текущая строка вывода), читают sep (разделитель сегментов) и level
# (ступень); flush переносит готовую строку в out.
# add <текст>: дописать сегмент в текущую строку через разделитель.
add() {
  if [ -n "$cur" ]; then
    cur+="$sep"
  fi
  cur+="$1"
}

# flush: закончить текущую строку вывода; пустая строка в out не попадает.
flush() {
  if [ -n "$cur" ]; then
    if [ -n "$out" ]; then
      out+=$'\n'
    fi
    out+="$cur"
    cur=""
  fi
}

# pct_segment <подпись> <процент> [темп] [отсчёт]: сегмент
# «подпись NN% 1.3× (resets in 2h29m)»; < 60% — без цвета, 60–79% или есть
# темп (он выводится только от 1.0) — жёлтый, >= 80% — красный; отсчёт — без
# цвета, на ступенях после полной — без слов: «2h29m». Процент пуст — сегмента
# нет.
pct_segment() {
  local color="" off="" text
  [ -n "$2" ] || return 0
  if [ "$2" -ge 80 ]; then
    color="$red"
  elif [ "$2" -ge 60 ] || [ -n "${3:-}" ]; then
    color="$yellow"
  fi
  if [ -n "$color" ]; then
    off="$reset"
  fi
  text="$color$1 $2%"
  if [ -n "${3:-}" ]; then
    text+=" $3$times"
  fi
  text+="$off"
  if [ -n "${4:-}" ]; then
    if [ "$level" -eq 0 ]; then
      text+=" (resets in $4)"
    else
      text+=" $4"
    fi
  fi
  add "$text"
}

# render <ступень> [short]: собрать строку статуса в out; short — ветка в
# коротком виде (branch_short, см. layout).
#   0 — полная: user@host:папка | модель ◔ effort | Context … | 5h … (resets in
#       2h29m) | 7d … | cache warm 31m | ветка;
#   1 — средняя: без user@host, effort и слов —
#       папка | модель | Ctx … | 5h … 2h29m | 7d … | cache 31m | ветка;
#   2 — сжатая: без папки и модели, через « · »;
#   3 — те же сегменты в две строки: контекст и лимиты / кэш и ветка;
#   4 — в три строки: контекст и 5h / 7d / кэш и ветка.
# На ступенях 2–4 показать бывает нечего (данных ещё нет, папка не в
# репозитории) — тогда выводится название модели.
render() {
  local level="$1" sep=' | ' cur="" label=Context text shown_branch="$branch"
  out=""
  if [ "${2:-}" = short ]; then
    shown_branch="$branch_short"
  fi
  case "$level" in
    0)
      cur="$green$user@$host$reset:$blue$short_dir$reset"
      text="$model"
      if [ -n "$effort" ]; then
        text+=" $effort_sep $effort"
      fi
      add "$text"
      ;;
    1)
      if [ -n "$short_dir" ]; then
        cur="$blue$short_dir$reset"
      fi
      add "$model"
      ;;
    *) sep=" $dot " ;;
  esac
  if [ "$level" -gt 0 ]; then
    label=Ctx
  fi

  # Контекст и лимиты подписки: пятичасовое окно и неделя.
  pct_segment "$label" "$ctx"
  pct_segment 5h "$limit_5h" "$pace_5h" "$resets_5h"
  if [ "$level" -eq 4 ]; then
    flush
  fi
  pct_segment 7d "$limit_7d" "$pace_7d"
  if [ "$level" -ge 3 ]; then
    flush
  fi

  # Кэш промпта: остаток до истечения (жёлтый, когда истекает) либо cold и
  # сколько токенов перекэширует следующий запрос.
  text=""
  case "$cache_kind" in
    warm | soon)
      if [ "$level" -eq 0 ]; then
        text="cache warm $cache_text"
      else
        text="cache $cache_text"
      fi
      if [ "$cache_kind" = soon ]; then
        text="$yellow$text$reset"
      fi
      if [ -n "$cache_tier" ] && [ "$level" -eq 0 ]; then
        text+=" ($cache_tier ttl)"
      elif [ -n "$cache_tier" ]; then
        text+=" ($cache_tier)"
      fi
      ;;
    cold)
      text="cache cold"
      if [ -n "$cache_text" ] && [ "$level" -eq 0 ]; then
        text+=" $dot $cache_text"
      elif [ -n "$cache_text" ]; then
        text+=" $cache_text"
      fi
      ;;
    *) ;;
  esac
  if [ -n "$text" ]; then
    add "$text"
  fi

  # Git-ветка со значком Powerline, если есть.
  if [ -n "$shown_branch" ]; then
    add "$branch_icon$shown_branch"
  fi
  flush
  if [ -z "$out" ]; then
    out="$model"
  fi
}

# visible <строка>: число видимых знаков строки — в vis. Вызывать под LC_ALL=C:
# счёт идёт по байтам и не зависит от локали пользователя.
# - Цвета убираются; из каждого знака UTF-8 остаётся один байт (байты
#   продолжения 0x80–0xBF не считаются).
# - Не считаются знаки без ширины, которые clean пропускает: комбинирующие
#   U+0300–U+036F (буквы «й» и «ё» в именах macOS — две кодовые точки) и
#   вариационные селекторы U+FE00–U+FE0F. Набор не исчерпывающий; те же байты
#   пропускает срез ветки в layout — менять только вместе. Мягкий перенос
#   U+00AD считается знаком: одни терминалы рисуют его дефисом, другие не
#   рисуют вовсе, а недосчитать ширину хуже, чем пересчитать, — строка с ним
#   сожмётся чуть раньше. У ветки на ступенях после полной следом пробуется
#   короткий вид, где переносов нет.
# - Знак двойной ширины (иероглиф, эмодзи) считается за один, одиночный байт
#   0x80–0xBF вне UTF-8 не считается вовсе: строка с ними может оказаться
#   длиннее экрана, и Claude Code обрежет её сам.
visible() {
  local color
  vis="$1"
  for color in "$green" "$blue" "$yellow" "$red" "$reset"; do
    if [ -n "$color" ]; then
      vis="${vis//"$color"/}"
    fi
  done
  vis="${vis//$'\314'[$'\200'-$'\277']/}"
  vis="${vis//$'\315'[$'\200'-$'\257']/}"
  vis="${vis//$'\357\270'[$'\200'-$'\217']/}"
  vis="${vis//[$'\200'-$'\277']/}"
  vis="${#vis}"
}

# fits <видимых знаков>: каждая строка out не длиннее бюджета; пустой out не
# подходит. Вызывать под LC_ALL=C.
fits() {
  local rest="$out" line
  [ -n "$out" ] || return 1
  while :; do
    line="${rest%%$'\n'*}"
    visible "$line"
    [ "$vis" -le "$1" ] || return 1
    [ "$rest" != "$line" ] || return 0
    rest="${rest#*$'\n'}"
  done
}

# scrub [vs]: убрать из short (локальная переменная layout) мягкие переносы, а
# с аргументом vs — и вариационные селекторы. После каждого удаления значение
# чистится заново (clean) и так до неизменности: вырезанные байты могли
# разделять половинки знака, который clean обязан убрать (смена направления
# письма, управляющий C1). Не сошлось за восемь проходов — short пуст.
scrub() {
  local prev="" passes=0
  while [ "$short" != "$prev" ]; do
    if [ "$passes" -ge 8 ]; then
      short=""
      return 0
    fi
    passes=$((passes + 1))
    prev="$short"
    short="${short//$'\302\255'/}"
    if [ -n "${1:-}" ]; then
      short="${short//$'\357\270'[$'\200'-$'\217']/}"
    fi
    if [ "$short" != "$prev" ]; then
      clean short
    fi
  done
}

# needs_cut: short длиннее 120 байт или 20 видимых знаков. У значения до 120
# байт число видимых знаков остаётся в vis; у более длинного оно не считается.
needs_cut() {
  vis=0
  if [ "${#short}" -gt 120 ]; then
    return 0
  fi
  visible "$short"
  [ "$vis" -gt 20 ]
}

# layout <видимых знаков>: выбрать первую строку, которая помещается, — ступени
# 0, 1, 2, 3 по порядку; на ступенях 1–3 следом пробуется та же ступень с
# веткой в коротком виде, если он отличается. Не поместилась ни одна —
# ступень 4 (три строки) с веткой в коротком виде, уже без проверки длины: на самом
# узком экране и она может оказаться длиннее, остаток обрежет Claude Code.
# - Короткий вид ветки (branch_short) — она же без мягких переносов, не
#   длиннее 20 видимых знаков и 120 байт (не считая «…»). Он пробуется, когда
#   отличается от самой ветки, и всегда выводится на ступени 4.
# - Мягкие переносы убираются всегда (scrub): в длине они считаются, и цепочка
#   их заняла бы все места и скрыла имя. Вариационные селекторы убираются,
#   только если имя и без переносов приходится укорачивать (scrub vs): срез
#   считает их знаками, и цепочка селекторов вытеснила бы имя; имя, которое
#   помещается, селекторы сохраняет — они задают вид эмодзи.
# - Очистка не сошлась, не осталось ничего или остались одни знаки без ширины
#   — короткий вид «…». Сама ветка при этом не меняется: там, где она
#   помещается, она выводится как есть (она уже прошла clean). Граница: у
#   имени длиннее 120 байт на «одни знаки без ширины» проверяется не срез —
#   цепочка комбинирующих знаков может занять его весь, и от имени останется
#   начало или одно «…».
# - Длиннее 20 видимых знаков — остаются 19 и «…»; длиннее 120 байт — столько
#   знаков, сколько уместилось в 120 байт, и «…». Счёт по байтам: начало знака
#   — любой байт, кроме 0x80–0xBF; комбинирующие знаки остаются при своей букве
#   и не считаются (те же байты, что в visible: менять только вместе).
# - Упёршись в предел 120 байт посреди знака, срез отступает к его началу (не
#   дальше трёх байтов — столько продолжений у самого длинного знака).
#   Начальный байт, оказавшийся последним перед «…», отбрасывается: в UTF-8
#   такого не бывает, а в имени не в UTF-8 это оборванный знак (цена: если
#   такой байт был посчитан 19-м знаком, в коротком виде их 18).
# - Ветка длиннее 255 байт на узком экране выводится только в коротком виде —
#   на всех ступенях: длина строки с такой веткой не считается вовсе. Иначе
#   объём вывода рос бы с длиной чужого имени (имя из байтов без ширины
#   «помещалось» бы целиком), а счёт длины строки на bash 3.2 стоил бы секунды
#   (замена по шаблону там стоит «длина × совпадения»). Сам scrub идёт по
#   всему имени — на bash 3.2 имя в несколько килобайт всё ещё стоит до секунд.
# - Пустой вывод не выбирается никогда: если показать нечего на всех ступенях
#   (нет даже названия модели — пустой ввод), выводится полная строка.
layout() {
  local LC_ALL=C budget="$1" level short="$branch" i=0 n=0
  local branch="$branch"
  scrub
  if needs_cut; then
    scrub vs
  fi
  if needs_cut; then
    while [ "$i" -lt 120 ]; do
      case "${short:i:2}" in
        [$'\200'-$'\277']*) ;;
        $'\314'[$'\200'-$'\277'] | $'\315'[$'\200'-$'\257']) ;;
        *)
          n=$((n + 1))
          [ "$n" -lt 20 ] || break
          ;;
      esac
      i=$((i + 1))
    done
    for n in 1 2 3; do
      case "${short:i:1}" in
        [$'\200'-$'\277']) i=$((i - 1)) ;;
        *) break ;;
      esac
    done
    if [ "$i" -gt 0 ]; then
      case "${short:$((i - 1)):1}" in
        [$'\300'-$'\377']) i=$((i - 1)) ;;
        *) ;;
      esac
    fi
    branch_short="${short:0:i}$ellipsis"
  elif [ "$vis" -eq 0 ]; then
    if [ -n "$branch" ]; then
      branch_short="$ellipsis"
    fi
  else
    branch_short="$short"
  fi
  if [ "${#branch}" -gt 255 ]; then
    branch="$branch_short"
  fi
  for level in 0 1 2 3; do
    render "$level"
    if fits "$budget"; then
      return 0
    fi
    if [ "$level" -gt 0 ] && [ "$branch_short" != "$branch" ]; then
      render "$level" short
      if fits "$budget"; then
        return 0
      fi
    fi
  done
  render 4 short
  if [ -z "$out" ]; then
    render 0
  fi
}

# Ширина терминала — COLUMNS (её задаёт Claude Code); видно на четыре знака
# меньше — поля строки статуса, проверено на 2.1.294. Строка сжимается только
# на узком экране — уже narrow_below колонок (телефон); от этой ширины, на
# компьютере, она всегда полная, даже если не помещается. Нет значения, не
# число из 1–4 цифр или меньше 20 — тоже полная. Цифры в проверке перечислены
# поимённо: диапазон 0-9 в локали пользователя пропустил бы и цифры других
# письменностей, а на них арифметика bash падает. Потолок в четыре цифры — от
# переполнения. При смене ширины окна скрипт заново не запускается — ступень
# сменится со следующим обновлением строки.
narrow_below=80
branch_short="$branch"
cols="${COLUMNS:-}"
cols_re='^[0123456789]{1,4}$'
if [[ "$cols" =~ $cols_re ]]; then
  cols=$((10#$cols))
else
  cols=0
fi
if [ "$cols" -ge 20 ] && [ "$cols" -lt "$narrow_below" ]; then
  layout "$((cols - 4))"
else
  render 0
fi
printf '%s' "$out"
```

После создания файла сделай его исполняемым — выполни через Bash:

```bash
chmod +x ~/.claude/statusline.sh
```

### 3. Пропиши конфиг в settings.json

Перед редактированием прочитай `~/.claude/settings.json` и убедись, что текущий JSON валиден.

Добавь секцию `statusLine` — поведение зависит от состояния файла:

**Файл отсутствует** — создай с минимальным содержимым:
```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh"
  }
}
```

**Файл существует и равен `{}`** — запиши:
```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh"
  }
}
```

**Файл существует с другими ключами** — используй Edit для точечного добавления рядом с существующими ключами. Не перезаписывай весь файл.

**Секция `statusLine` уже есть** (пользователь согласился заменить свою команду в шаге 1) — замени Edit'ом только значение `command`; второй ключ `statusLine` не добавляй — дубль ключа ломает JSON.

> Если строка статуса не появляется после настройки, замени `~` на абсолютный путь, например `/home/username/.claude/statusline.sh` — некоторые окружения не раскрывают `~` без shell.

### 4. Подтверди результат

После настройки:
- Сообщи пользователю, что statusline настроен
- **Если в секции `statusLine` нет `refreshInterval`** — спроси, добавить ли `"refreshInterval": 30`: без него отсчёты до сброса лимита и до истечения кэша в простое не тикают (строка перерисовывается только по событиям сессии). Согласен — перечитай `~/.claude/settings.json`, убедись, что JSON валиден, и добавь поле Edit'ом в существующую секцию `statusLine`; отказ — не добавляй. Уже есть — не трогай и не спрашивай.
- Покажи итоговую конфигурацию — секцию `statusLine` после всех правок, включая `refreshInterval`, если он добавлен
- Предупреди, что изменения вступят в силу после перезапуска Claude Code (если сессия уже активна)
- **Если сессия идёт внутри tmux** — расскажи про мост: скрипт пишет процент контекста в опцию панели `@claude_ctx`, и её можно показать в строке статуса tmux. Покажи пример ниже и скажи, что это правка `~/.tmux.conf`, которую пользователь делает сам (после неё — `tmux source-file ~/.tmux.conf`); сам `~/.tmux.conf` не меняй без прямой просьбы. Если в шаге 0 не нашёлся `timeout` или tmux старше 3.0 — скажи, что мост работать не будет, и почему.

  Сегмент ставится **в начало** собственного `status-right` пользователя (здесь после сегмента — штатное значение tmux); длину поднять, иначе штатные 40 знаков обрежут строку:

  ```tmux
  set -g status-right-length 60
  set -g status-right '#{?#{m/r:^[0-9][0-9]?[0-9]?$,#{@claude_ctx}},CTX #{@claude_ctx}%% | ,}"#{=21:pane_title}" %H:%M %d-%b-%y'
  ```

  Ограничения, о которых стоит сказать: значение проверяется самим форматом (`#{m/r:…}` — 1–3 цифры) и без такой проверки его нельзя подставлять в команду внутри `#(…)`; опцию `@claude_ctx` нельзя задавать выше панели (`set -g`/`-w`/`-s`); после выхода из Claude старое число остаётся в панели, пока в ней снова не запустят Claude. Подробности — README плагина.

Затем автоматически проверь наличие Nerd Font / Powerline-шрифта — выполни через Bash:

```bash
fc-list 2>/dev/null | grep -iE "nerd|powerline|MesloLGS|FiraCode Nerd|JetBrainsMono Nerd|Hack Nerd"
```

**Если вывод непустой** (шрифт найден) — сообщи пользователю, что Nerd Font обнаружен, значок ветки должен отображаться корректно. На этом всё.

**Если вывод пустой** (шрифт не найден) — предупреди:

> «Nerd Font / Powerline-совместимый шрифт не обнаружен — значок ветки  может отображаться как □. Выберите вариант:
> 1. Установить Nerd Font автоматически.
> 2. Убрать значок из скрипта.»

Дождись выбора и выполни:

- **Вариант 1 — установить автоматически:**
  Определи ОС и доступный пакетный менеджер:
  - Linux + `apt`: `sudo apt install fonts-powerline`
  - Linux + `dnf`: `sudo dnf install powerline-fonts`
  - Linux + `pacman`: `sudo pacman -S powerline-fonts`
  - macOS + `brew`: `brew install --cask font-hack-nerd-font`

  Если подходящий менеджер найден — выполни установку.
  Если ни один не доступен — установить автоматически нельзя; напиши пользователю:
  > «Установите шрифт вручную: https://www.nerdfonts.com/font-downloads — скачайте любой шрифт, распакуйте, установите через менеджер шрифтов системы.»

  В любом случае (и при успешной автоустановке, и при ручной инструкции) напомни:
  > «После установки выберите этот шрифт в настройках вашего терминала и перезапустите его — без этого шага значок не появится.»

- **Вариант 2 — убрать значок:**
  Отредактируй `~/.claude/statusline.sh` — замени строку:
  ```
  branch_icon=$'\xee\x82\xa0 '
  ```
  на:
  ```
  branch_icon=""
  ```
  Строки `branch_icon=` в скрипте нет (пользователь оставил скрипт версии до 2.10.0) — замени в нём `printf ' | \xee\x82\xa0 %s' "$branch"` на `printf ' | %s' "$branch"`.

## Важно

- Никогда не удаляй существующий `~/.claude/statusline.sh` без явного разрешения пользователя — предложи сначала показать текущее содержимое
- `settings.json` — это JSON без комментариев; некорректное редактирование (незакрытая скобка, лишняя запятая) сломает конфигурацию — всегда проверяй валидность перед правками
- Значок ветки `` требует Nerd Font / Powerline-совместимого шрифта в терминале; если отображается `□` — замените в скрипте `branch_icon=$'\xee\x82\xa0 '` на `branch_icon=""` (в скрипте версии до 2.10.0 — уберите `\xee\x82\xa0 ` из строки `printf` с веткой)
- Разделитель `◔` (U+25D4) перед effort есть в большинстве моноширинных шрифтов, и проверка Nerd Font из шага 4 к нему не относится; если после названия модели отображается `□` — замените в скрипте значение `effort_sep` (`\xe2\x97\x94`; в скрипте версии до 2.10.0 эти байты стоят в строке `printf` с effort) на другой символ, например `\xc2\xb7` (`·`)
