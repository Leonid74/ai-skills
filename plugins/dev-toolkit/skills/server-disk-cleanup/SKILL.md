# Анализ и согласованная очистка места на диске

**Цель:** показать, чем занят диск Linux-сервера или dev-машины, отделить безопасно удаляемое от
того, что требует решения, и удалить **только то, что пользователь явно выбрал**. Выигрыш измеряется
реальным `df`, а не суммой оценок.

Скилл работает в пяти фазах: 0 — предусловия, 1 — разведка, 2 — проверка «не используется ли»,
3 — таблица и вопрос, 4 — выполнение выбранного, 5 — сверка и отчёт. Фазы 0–3 — **только чтение**.

Справочник по экосистемам вне ядра (dnf/yum, snap, flatpak, podman, npm/yarn/pnpm, pip/uv,
composer, go, cargo, Playwright) и список «установлено, не кеш» — `references/caches.md`. Читай его,
когда разведка нашла соответствующий каталог или менеджер.

## Согласие на удаление (главное правило)

- **Исходная просьба согласием не является** — ни «почисти», ни «освободи место», ни «удали всё
  лишнее», ни «проанализируй и удали безопасное». Она запускает только фазы 0–3.
- **Согласие — только ответ на прямой вопрос фазы 3**, в котором названы **номера** пунктов таблицы
  (например `1, 3, 5–7`). Выполняются ровно названные номера.
- Ответ без номеров («ок», «давай», «всё безопасное», «всю группу А») — **не согласие**: переспроси,
  перечислив номера, которые ты понял, и дождись подтверждения.
- Согласие **одноразовое и адресное**: не распространяется на кандидатов, найденных позже, и на пункт,
  который изменился при повторной проверке фазы 4 — о нём спроси заново.
- Разрешение инструмента (permission-промпт) тоже согласием на пункт **не является**: команда
  запускается, только если её пункт уже выбран в ответе на вопрос.

## Политика удаления (действует независимо от хуков)

Эти правила — собственные правила скилла. Хук `guard-bash` плагина dev-toolkit часть из них
страхует механически, но у пользователя его может не быть — соблюдай их в любом случае.

- **Только адресные команды.** `docker rmi <ID…>`, `docker volume rm <имя>`, `docker rm <ID>` —
  по списку из таблицы. Запрещены `docker system prune`, `docker image prune -a`,
  `docker volume prune`, `--volumes`: они удалят базовые образы деплоя, инструменты без запущенного
  контейнера и тома с данными. Кеш сборки — только `docker builder prune --filter until=168h`.
- **Кеши — командами их менеджеров** (`apt-get clean`, `npm cache clean --force`, `pip cache purge`,
  `go clean -cache`, `composer clear-cache` — см. справочник); `rm` — только если своей команды у
  менеджера нет.
- **Рекурсивное удаление:**
  - внутри `/tmp` — **по одному абсолютному литеральному пути** на аргумент, без масок (`*`),
    переменных, `cd` + относительного пути. Маску хук проверяет как текст, а shell раскроет её при
    исполнении — так задевается рабочий каталог живой сессии;
  - вне `/tmp` — **не выполняй сам**: дай пользователю готовую команду для запуска через `! …`
    (`! rm -rf -- '/абсолютный/путь'`) и дождись, пока он её выполнит;
  - **никаких обходов**: `find -delete`, `find -exec rm`, `xargs rm`, `shutil.rmtree`/`File::Path`,
    генерируемые списки путей. Если хук заблокировал команду — не переформулируй её, отдай
    пользователю.
- **Лог, в который идёт запись, не удаляй** — только `truncate -s 0` (пункт группы Б). Процесс
  продолжит писать в удалённый inode, и место не вернётся.
- **Удалённые, но открытые файлы** (`lsof +L1`) удалением не лечатся — место вернёт перезапуск
  процесса-держателя. Это пункт «найденных проблем», не очистки.
- **Каталог текущей сессии Claude Code** (родитель scratchpad-каталога из системного промпта) и
  рабочие каталоги живых сессий не удаляются никогда.

## Секреты на разведке

- `docker inspect` — **только с `--format`** (метки, монтирования, образ). Полный вывод содержит
  `Config.Env` с паролями.
- Не выводи окружение контейнеров и процессов (`docker exec … env`, `/proc/*/environ`,
  `docker compose config`).
- Crontab и скрипты бэкапов **не печатай целиком** — ищи в них нужные строки `grep`'ом (пути,
  `KEEP`/`RETENTION`, имена каталогов): в них бывают пароли FTP/S3.
- Поиск по коду — `grep -rl` (только имена файлов): совпадение может оказаться в файле с секретами.

## Фаза 0 — предусловия

```bash
uname -sr; head -3 /etc/os-release
findmnt -D -t nosquashfs,notmpfs,nodevtmpfs,nooverlay   # точки монтирования, где что лежит
df -B1M -x tmpfs -x devtmpfs -x squashfs -x overlay      # замер «до» — сохрани вывод
df -i -x tmpfs -x devtmpfs -x squashfs -x overlay        # кончаются inode, а не байты?
sudo -n true && echo sudo-ok                              # sudo без пароля?
command -v docker && docker info --format '{{.Driver}} {{.DockerRootDir}}'
```

- `sudo -n` не прошёл — не жди пароля в своей команде: разведку делай без `sudo`, а для команд с
  `sudo` отдавай пользователю `! sudo …`. Отметь в отчёте, что без `sudo` часть размеров неполна
  (например, `journalctl --disk-usage` без него показывает только журнал пользователя).
- Кончаются inode (`IUse%` > 90%) — ищи каталоги с миллионами мелких файлов, а не крупные файлы.

## Фаза 1 — разведка (только чтение)

Все `du` — с `-x` (не переходить на другие ФС) и `timeout`, чтобы не зависнуть на сетевом монтировании:

```bash
sudo -n timeout 120 du -xh --max-depth=1 / 2>/dev/null | sort -rh | head -20
sudo -n timeout 120 du -xh --max-depth=2 /var /home /tmp /opt 2>/dev/null | sort -rh | head -40
```

Дальше — по найденному, по категориям:

- **Docker:** `docker system df` и `docker system df -v` (размеры образов, томов, кеша сборки);
  `docker images --format '{{.ID}} {{.Repository}}:{{.Tag}} {{.CreatedSince}} {{.Size}}'`;
  `docker ps -a --format '{{.ID}} {{.Names}} {{.Image}} {{.Status}} {{.Mounts}}'`;
  метки томов — `docker volume inspect --format '{{.Name}} {{json .Labels}}' <том>`
  (`com.docker.volume.anonymous`, `com.docker.compose.project`); логи контейнеров —
  драйвер `docker info --format '{{.LoggingDriver}}'`, размеры для `json-file` —
  `sudo -n find /var/lib/docker/containers -name '*-json.log' -size +100M -exec du -sh {} +`
  (маска в пути раскрылась бы до `sudo`, без прав на каталог).
- **Журнал systemd:** `sudo -n journalctl --disk-usage`.
- **Пакеты:** `du -sh /var/cache/apt`; `apt-get -s autoremove | grep '^Remv'` (что снимет autoremove).
- **Ядра:** `uname -r` против `dpkg -l 'linux-image-*' 'linux-modules-*' 'linux-headers-*' | awk '/^ii/{print $2}'`.
- **Пользовательские кеши:** `du -sh ~/.cache/* ~/.npm ~/.local/share/* 2>/dev/null | sort -rh | head`.
- **Claude Code:** `~/.local/share/claude/versions` (текущая — `claude --version` и
  `readlink -f "$(command -v claude)"`); каталоги сессий `/tmp/claude-<uid>/<проект>/<сессия>`
  (`du -sh /tmp/claude-$(id -u)/*/* | sort -rh`); `~/.cache/gh/run-log-*.zip`.
- **Удалённые, но открытые файлы:** `sudo -n lsof -nP +L1 2>/dev/null | awk 'NR>1{s[$1" "$2]+=$7} END{for(k in s) print s[k], k}' | sort -rn | head`.
- **Core-дампы и аварии:** `coredumpctl list 2>/dev/null | tail`, `du -sh /var/crash /var/lib/systemd/coredump`.
- **Бэкапы:** куда пишутся и сколько копий хранится — `crontab -l | grep -v '^#'` и `grep`'ом по
  скриптам из crontab (`KEEP`, пути); размеры копий — `ls -la` каталога бэкапов.

Всё крупнее ~100 МБ, что не удалось отнести к категории, — в строку «неопознанное» таблицы, не в
кандидаты.

## Фаза 2 — проверка «не используется ли»

Для каждого кандидата — доказательство, что он не нужен, а не предположение по имени или размеру.

- **Образ Docker:** не нужен, если одновременно:
  - нет контейнеров от него, **включая остановленные**: `docker ps -a --filter ancestor=<образ>`;
  - имя (с тегом и **без тега**) не встречается в коде и документации: `grep -rlF '<имя>'` по
    каталогам проектов, включая `*.md`, `doc/`, `.dev/`, Makefile, compose-файлы, CI-конфиги,
    `~/bin`, `~/.claude/{skills,plugins,hooks}` — не только `*.sh`/`*.yml`/`Dockerfile`;
  - он не базовый для деплоя: `FROM` и `COPY --from=` во всех Dockerfile;
  - он старше **168 часов** (`CreatedSince`) — свежее не предлагай: скорее всего, идёт работа.

  Инструменты без постоянного контейнера (линтеры, сканеры, `composer`, `node`) живут как образы без
  контейнеров — это не мусор, если они упомянуты в скриптах. Образ, упомянутый в документации
  **другого** проекта, — только в группу Б.
- **Том Docker:** не смонтирован ни одним контейнером (включая остановленные — поле `Mounts`);
  именованный том compose-проекта — всегда группа Б (данные, необратимо).
- **Каталог:** его не держат процессы — `pgrep -a <имя>`,
  `timeout 30 lsof +D <каталог> 2>/dev/null` (пустой вывод — никто не держит; stderr засоряют
  предупреждения об overlay-ФС Docker); он
  **холодный** — самый свежий файл внутри старше порога:
  `find <каталог> -xdev -type f -mtime -7 -print -quit` пусто. mtime самого каталога не
  доказательство, большой размер — тоже.
- **Артефакт сборки** (`node_modules`, `target/`, `vendor/`, `.venv`) — артефакт, только если рядом
  есть файл проекта (`package.json`, `Cargo.toml`, `composer.json`, `pyproject.toml`); без маркера —
  «неопознанное».
- **Каталоги сессий Claude Code:** исключи каталог текущей сессии; `pgrep -a claude` — живые сессии
  (их каталоги тоже исключаются); `lsof +D` по остальным.
- **Установленное, не кеш** (тулчейны, версии рантаймов, браузеры Playwright) — не кандидат на `rm`;
  список и команды менеджеров — в справочнике.

## Фаза 3 — таблица и вопрос

Покажи таблицу и **остановись**. Нумерация **сквозная через обе группы** (А: 1–5, Б: 6–11), чтобы
ответ состоял из одних номеров без указания группы.

**Группа А — без риска** (всё восстанавливается само или повторной загрузкой):

| № | Что | Размер | Команда | Последствие / цена восстановления |
|---|-----|--------|---------|-----------------------------------|

**Группа Б — нужно решение** (потеря данных, истории, пересборка, чужой проект):

| № | Что | Размер | Команда | Последствие / цена восстановления |
|---|-----|--------|---------|-----------------------------------|

Ниже таблиц, **без номеров** (их нельзя выбрать):

- **Не трогаю** — что и почему (используется, установлено, свежее, работающее ядро, …).
- **Неопознанное > 100 МБ** — путь, размер, «нужно разобраться».
- **Личные данные** — крупные документы/медиа в домашних каталогах: только к сведению.
- **Найденные проблемы** — сообщить, не чинить без отдельной просьбы: удалённые, но открытые файлы;
  логи контейнеров без `max-size`; журнал без `SystemMaxUse`; core-дампы (приложение падает в
  цикле — чинить причину); кончающиеся inode.

Правила таблицы:

- Колонка «Команда» — ровно та команда, которая будет выполнена; для рекурсивного удаления вне
  `/tmp` — пометка «выполнит пользователь через `! …`».
- **Цифры Docker — «оценка»**: при containerd-snapshotter и общих слоях `docker system df` не
  совпадает с тем, что вернёт диск. Не складывай перекрывающиеся размеры (каталог и его подкаталог,
  образы с общими слоями) в итог — итог покажет `df` в фазе 5.
- Удаление образа — укажи цену: следующий деплой/запуск скачает или соберёт его заново.

Затем задай **прямой вопрос** и закончи ход:

> Какие пункты выполнить? Ответьте номерами (например: `1, 3, 5–7`). Пока номера не названы, ничего
> не удаляется.

## Фаза 4 — выполнение выбранного

Только номера из ответа на вопрос фазы 3. Для **каждого** пункта, непосредственно перед командой:

1. **Повторная проверка.** Объект существует; размер близок к табличному (`du -sxB1M`); его не
   держат процессы (`lsof +D … 2>/dev/null` / `pgrep`); для образа — тот же ID
   (`docker image inspect --format '{{.Id}}' <образ>`), контейнеров от него по-прежнему нет. Что-то
   изменилось — пункт **пропусти**, в отчёт — «изменился, нужно новое согласие».
2. **Проверка пути** (для файлов и каталогов): `realpath -e -- '<путь>'` совпадает с путём из
   таблицы; `test -L` — не символическая ссылка; путь не `/`, не `$HOME`, не точка монтирования
   (`findmnt -M '<путь>'` пусто). Не прошло — пункт пропустить.
3. **Команда** — ровно из колонки «Команда». Рекурсивное удаление вне `/tmp` и команды с `sudo` при
   недоступном `sudo -n` — отдай пользователю строкой `! …` и продолжай, когда он сообщит о запуске.

Перед первым пунктом запомни список томов и запущенных контейнеров
(`docker volume ls -q | sort`, `docker ps --format '{{.Names}} {{.Status}}'`) и активных сервисов
(`systemctl --failed --no-legend`) — для сверки в фазе 5.

## Фаза 5 — сверка и отчёт

- `df -B1M` «после» против «до» — **реальный выигрыш** по каждой ФС; `docker system df` — отдельно
  («освобождено в Docker» ≠ «возвращено диску»).
- Инварианты: список томов не изменился (кроме удалённых по согласию), запущенные контейнеры
  по-прежнему `Up`, новых упавших сервисов нет. Нарушение — первым пунктом отчёта.
- Отчёт: выполненные пункты; пропущенные и почему (изменились, не прошли проверку пути, ждут запуска
  пользователем через `! …`); что осталось на потом (например, ядро до перезагрузки).

## Ловушки

- **Работающее ядро (`uname -r`) не трогать.** Новое ядро установлено, но не загружено — старое
  удаляется только после перезагрузки (`apt autoremove --purge`), а перезагрузка — решение
  пользователя, не часть скилла.
- **Локальные бэкапы сокращать только после сверки размеров удалённой копии** (FTP/S3 листингом с
  размерами): журнал выгрузки пишет «OK», не проверяя размер, и пустой дамп тоже считается «OK».
- **`docker builder prune` без `--filter until=`** заставит следующую сборку/автодеплой собирать
  образ с нуля.
- **`npm cache clean --force` не чистит `~/.npm/_npx`** — это отдельный кандидат.
- **Playwright (`~/.cache/ms-playwright`)** — установленные браузеры, нужные для проверки HTML
  реальным рендером; по умолчанию «не трогаю».
