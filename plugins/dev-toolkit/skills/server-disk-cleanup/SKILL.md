# Анализ и согласованная очистка места на диске

**Цель:** показать, чем занят диск Linux-сервера или dev-машины, отделить безопасно удаляемое от
того, что требует решения, и удалить **только то, что пользователь явно выбрал**. Выигрыш измеряется
реальным `df`, а не суммой оценок.

Скилл работает в шести фазах: 0 — предусловия, 1 — разведка, 2 — проверка «не используется ли»,
3 — таблица и вопрос, 4 — выполнение выбранного, 5 — сверка и отчёт. Фазы 0–3 — **только чтение**.

Справочник `references/caches.md` — команды и группы для всего вне ядра этого файла: journald
(очистка), логи контейнеров Docker, dnf/yum, snap, flatpak, podman, npm/yarn/pnpm, pip/uv, composer,
go, cargo, gh, версии Claude Code, Playwright и список «установлено, не кеш». **Прочитай его до
таблицы фазы 3**, если разведка нашла любую из этих категорий: команду и группу для них бери оттуда,
не придумывай.

**Рабочий каталог `W`** — scratchpad-каталог сессии, если он назван в системном промпте, иначе
создай его: `mktemp -d`. Замеры «до», снимок инвариантов и вывод длинных команд пиши файлами в `W`:
контекст диалога может сжаться между фазами 0 и 5, файлы — нет.

## Согласие на удаление (главное правило)

- **Исходная просьба согласием не является** — ни «почисти», ни «освободи место», ни «удали всё
  лишнее», ни «проанализируй и удали безопасное». Она запускает только фазы 0–3.
- **Согласие — только номера пунктов таблицы, которые пользователь сам назвал в ответе на прямой
  вопрос фазы 3** (например `1, 3, 5–7`). Выполняются ровно названные номера.
- Ответ без номеров («ок», «давай», «да», «всё безопасное», «всю группу А») — **не согласие**:
  повтори вопрос и попроси назвать номера. **Не предлагай свой перечень номеров на подтверждение** —
  «да» в ответ на твой перечень номерами не является.
- Согласие **одноразовое и адресное**: не распространяется на кандидатов, найденных позже, и на пункт,
  который изменился при повторной проверке фазы 4 — о нём спроси заново тем же вопросом.
- Разрешение инструмента (permission-промпт) тоже согласием на пункт **не является**: команда
  запускается, только если её пункт уже выбран в ответе на вопрос.

## Политика удаления (действует независимо от хуков)

Эти правила — собственные правила скилла. Хук `guard-bash` плагина dev-toolkit страхует механически
только часть из них (рекурсивный `rm` вне `/tmp`, вывод окружения), а у пользователя его может не
быть — соблюдай их в любом случае.

- **Только адресные команды.** `docker rmi <ID…>`, `docker volume rm <имя>`, `docker rm <ID>` —
  по списку из таблицы. Запрещены `docker system prune`, `docker image prune -a`,
  `docker volume prune`, `--volumes`: они удалят базовые образы деплоя, инструменты без запущенного
  контейнера и тома с данными. Кеш сборки — только `docker builder prune -f --filter until=168h`:
  без фильтра следующая сборка/автодеплой соберёт образ с нуля, без `-f` команда ждёт `y/N` и в
  неинтерактивном запуске ничего не делает.
- **Команды, которые сами вычисляют, что удалить** (`apt autoremove`, `pnpm store prune` и т. п.), —
  только если в таблице показан их список по симуляции (`apt-get -s autoremove`); в фазе 4 симуляцию
  повтори, и если список изменился — пункт пропусти и спроси заново.
- **Кеши — командами их менеджеров** (`sudo apt-get clean`, `npm cache clean --force`,
  `pip cache purge`, `go clean -cache`, `composer clear-cache` — см. справочник); `rm` — только если
  своей команды у менеджера нет.
- **Безопасный путь.** В команду (любую, и read-only) подставляется только абсолютный путь из
  символов `A-Z a-z 0-9 / . _ - + @ :` — без кавычек, после `--`. Путь с другими символами
  (пробел, кавычки, `$`, `` ` ``, `;`, перевод строки, не-ASCII) в команды не подставляй: такой объект
  — строкой «неопознанное» с пометкой «необычное имя — разобрать вручную». Имена каталогов бывают
  чужими данными (другой пользователь `/tmp`, распакованный архив), и `x'; cmd; '` в имени иначе
  превращается в команду.
- **Рекурсивное удаление:**
  - внутри `/tmp` — сам, **только своего** объекта (`stat -c %U -- <путь>` — текущий пользователь),
    **без `sudo`**, по одному безопасному пути на аргумент, без масок (`*`), переменных, `cd` +
    относительного пути. Маску хук проверяет как текст, а shell раскроет её при исполнении — так
    задевается рабочий каталог живой сессии;
  - вне `/tmp` или чужой объект — **не выполняй сам**: дай пользователю готовую команду
    (`rm -rf -- /абсолютный/путь`) и дождись, пока он её выполнит (как запускать — «Команды
    пользователю»);
  - **никаких обходов**: `find -delete`, `find -exec rm`, `xargs rm`, `shutil.rmtree`/`File::Path`,
    генерируемые списки путей. Если хук заблокировал команду — не переформулируй её, отдай
    пользователю.
- **Лог, в который идёт запись, не удаляй** — только `truncate -s 0` (пункт группы Б). Процесс
  продолжит писать в удалённый inode, и место не вернётся.
- **Удалённые, но открытые файлы** (`lsof +L1`) удалением не лечатся — место вернёт перезапуск
  процесса-держателя. Это пункт «найденных проблем», не очистки.
- **Каталоги сессий Claude Code** — текущей (родитель `W`, если `W` — scratchpad) и всех живых —
  не удаляются никогда. Живую сессию выдаёт каталог `<сессия>/tasks`, открытый процессом `claude`
  (фаза 2).

## Команды пользователю

Команду, которую выполняет пользователь, давай готовой строкой и говори, где её запускать:

- без `sudo` — в чате через `! <команда>`;
- **с `sudo`, когда `sudo -n` не прошёл, — только в отдельном терминале**, не через `!`: в режиме `!`
  нет терминала, `sudo` не может спросить пароль и молча завершается, будто команда прошла.

После его сообщения **проверь результат сам** (путь исчез — `test -e`, объект удалён — `docker image
inspect`, размер изменился — `du`/`df`); не подтвердилось — пункт в отчёт как «не выполнен».

## Секреты на разведке

- `docker inspect` — **только с `--format`** (метки, монтирования, образ). Полный вывод содержит
  `Config.Env` с паролями.
- Не выводи окружение контейнеров и процессов (`docker exec … env`, `/proc/*/environ`,
  `docker compose config`).
- Процессы — только имя и PID (`pgrep -l`, колонки `COMMAND`/`PID` у `lsof`), **не `pgrep -a` и не
  `ps aux`**: в аргументах командной строки бывают пароли (`--requirepass`, `--password=`).
- Crontab и скрипты бэкапов **не печатай целиком** — только расписание и путь команды (фильтр —
  фаза 1) или адресный `grep` по нужному (`KEEP`/`RETENTION`, пути): в них бывают пароли FTP/S3.
- Поиск по коду — `grep -rl` (только имена файлов): совпадение может оказаться в файле с секретами.

## Фаза 0 — предусловия

```bash
uname -sr; head -3 /etc/os-release; findmnt -no FSTYPE /
findmnt -D -t nosquashfs,notmpfs,nodevtmpfs,nooverlay
sudo -n true && echo sudo-ok
command -v docker && docker info --format '{{.Driver}} {{.DockerRootDir}}'
```

Замер «до» — в файлы `W` (те же команды повторит фаза 5; `df /` отдельно — в контейнере корень
бывает `overlay`, и фильтр `-x overlay` его бы выбросил):

```bash
{ df -B1M -x tmpfs -x devtmpfs -x squashfs -x overlay; df -B1M /; } > W/df-before.txt
{ df -i -x tmpfs -x devtmpfs -x squashfs -x overlay; df -i /; } > W/df-i-before.txt
```

- **`sudo -n` не прошёл** — те же команды разведки запускай **без `sudo -n`** (иначе они молча
  вернут пусто) и отметь в отчёте, что без `sudo` картина неполна: чужие каталоги не читаются,
  `lsof` не видит чужих процессов, `journalctl --disk-usage` показывает только журнал пользователя.
- **Docker не отвечает** (`docker info` упал: демон, права на сокет, другой `DOCKER_HOST`) —
  Docker-категорию пропусти целиком и назови причину в отчёте.
- **Корень на btrfs/zfs** — проверь снапшоты (`sudo -n snapper list`, `sudo -n btrfs subvolume
  list -s /`, `zfs list -t snapshot`): пока снапшот жив, удаление файлов место не вернёт, а `du -x`
  его не видит. Снапшоты — в «найденные проблемы», не в кандидаты.
- **Кончаются inode** (`IUse%` > 90%) — ищи каталоги с миллионами мелких файлов, а не крупные файлы.

## Фаза 1 — разведка (только чтение)

Все `du` — с `-x` (не переходить на другие ФС), `-d` (понимают и GNU, и BusyBox; `--max-depth` —
только GNU) и `timeout`; вывод — в файл, код возврата — отдельно: `rc=124` (сработал таймаут) или
другой ненулевой — **вывод неполный**, так и пометь.

```bash
sudo -n timeout 120 du -xh -d 1 / 2>/dev/null > W/du-root.txt; echo "rc=$?"; sort -rh W/du-root.txt | head -20
sudo -n timeout 120 du -xh -d 2 /var /home /tmp /opt 2>/dev/null > W/du-2.txt; echo "rc=$?"; sort -rh W/du-2.txt | head -40
```

Дальше — по найденному, по категориям:

- **Docker:** `docker system df` и `docker system df -v` (размеры образов, томов, кеша сборки);
  `docker images --format '{{.ID}} {{.Repository}}:{{.Tag}} {{.Size}}'`;
  `docker ps -a --no-trunc --format '{{.Names}} {{.Image}} {{.Status}} {{.Mounts}}'` (без `--no-trunc`
  имена томов в `Mounts` обрезаются); метки томов —
  `docker volume inspect --format '{{.Name}} {{json .Labels}}' <том>`; логи контейнеров — по
  справочнику.
- **Журнал systemd:** `sudo -n journalctl --disk-usage`.
- **Пакеты:** `du -sh /var/cache/apt`; `apt-get -s autoremove | grep '^Remv'` (что снимет autoremove).
- **Ядра:** `uname -r` против `dpkg -l 'linux-image-*' 'linux-modules-*' 'linux-headers-*' | awk '/^ii/{print $2}'`
  (не Debian — справочник).
- **Пользовательские кеши:** `du -sh ~/.cache/* ~/.npm ~/.local/share/* 2>/dev/null | sort -rh | head`.
- **Claude Code:** версии и `~/.cache/gh` — по справочнику; каталоги сессий
  `/tmp/claude-<uid>/<проект>/<сессия>` — `du -sh /tmp/claude-$(id -u)/*/* | sort -rh`.
- **Удалённые, но открытые файлы:** `sudo -n lsof -nP +L1 2>/dev/null | awk 'NR>1{s[$1" "$2]+=$7} END{for(k in s) print s[k], k}' | sort -rn | head`.
- **Core-дампы и аварии:** `coredumpctl list 2>/dev/null | tail`, `du -sh /var/crash /var/lib/systemd/coredump`.
- **Бэкапы:** куда пишутся и сколько копий хранится. Crontab — только расписание и путь команды
  (значения переменных и аргументы скрыты):

  ```bash
  crontab -l 2>/dev/null | awk '/^[[:space:]]*(#|$)/{next} $1~/=/{sub(/=.*/,"",$1); print "переменная", $1; next} {k=($1~/^@/)?2:6; n=k; while($n~/=/) n++; s=""; for(i=1;i<k;i++) s=s $i " "; print s $n}'
  ```

  По скриптам из crontab — адресный `grep` (`KEEP`, пути); размеры копий — `ls -la` каталога бэкапов.

Всё крупнее ~100 МБ, что не удалось отнести к категории, — в строку «неопознанное» таблицы, не в
кандидаты.

## Фаза 2 — проверка «не используется ли»

Для каждого кандидата — доказательство, что он не нужен, а не предположение по имени или размеру.
**Проверка, которая не выполнилась, доказательством не является**: сбой, таймаут, нехватка прав →
кандидат в «Не трогаю» с причиной «не удалось проверить», а не в таблицу.

- **Образ Docker:** не нужен, если одновременно:
  - нет контейнеров от него, **включая остановленные**: `docker ps -a --filter ancestor=<образ>`;
  - имя (с тегом и **без тега**) не встречается в коде и документации: `grep -rlF -- <имя>` по
    каталогам проектов, включая `*.md`, `doc/`, `.dev/`, Makefile, compose-файлы, CI-конфиги,
    `~/bin`, `~/.claude/{skills,plugins,hooks}` — не только `*.sh`/`*.yml`/`Dockerfile`;
  - он не базовый для деплоя: `FROM` и `COPY --from=` во всех Dockerfile;
  - он **появился на машине** больше 168 часов назад — `docker image inspect --format
    '{{.Metadata.LastTagTime}}' <образ>` (время pull/build/tag; `CreatedSince` — время сборки в
    реестре, не годится). Нулевое значение (`0001-01-01`) — считать свежим. Свежее не предлагай:
    скорее всего, идёт работа.

  Инструменты без постоянного контейнера (линтеры, сканеры, `composer`, `node`) живут как образы без
  контейнеров — это не мусор, если они упомянуты в скриптах. Образ, упомянутый в документации
  **другого** проекта, — только в группу Б.
- **Том Docker:** не смонтирован ни одним контейнером, включая остановленные:
  `docker ps -a --filter volume=<том> --format '{{.Names}}'` пусто. **Любой том — всегда группа Б**
  (именованный, анонимный, с меткой compose или без): в нём бывают данные БД, удаление необратимо.
- **Каталог не держат процессы:**
  `sudo -n timeout 30 lsof -nP +D <каталог> 2>/dev/null; echo "rc=$?"` — «не держат» только при
  **пустом выводе и `rc=1`**. `rc=124` (таймаут), `rc=127` (нет `lsof`) — проверка не выполнилась.
  Без `sudo` `lsof` видит только процессы текущего пользователя — доказательство годится лишь для
  каталогов в его домашнем каталоге и в `/tmp/claude-<uid>`.
- **Каталог холодный** — самый свежий файл внутри старше порога:
  `timeout 60 find <каталог> -xdev -type f -mtime -7 -print -quit 2>/dev/null; echo "rc=$?"` —
  холодный только при **пустом выводе и `rc=0`**; ненулевой `rc` (нечитаемые подкаталоги, таймаут)
  — проверка не выполнилась. mtime самого каталога не доказательство, большой размер — тоже.
- **Артефакт сборки** (`node_modules`, `target/`, `vendor/`, `.venv`) — артефакт, только если рядом
  есть файл проекта (`package.json`, `Cargo.toml`, `composer.json`, `pyproject.toml`); без маркера —
  «неопознанное». Восстановление — пересборка, поэтому группа Б.
- **Каталоги сессий Claude Code:** живые сессии —
  `timeout 30 lsof -nP +D /tmp/claude-$(id -u) 2>/dev/null | awk '$1=="claude"{print $NF}' | sort -u`
  (процесс `claude` держит открытым `<сессия>/tasks`; `pgrep` каталог сессии не называет). Их
  каталоги и каталог текущей сессии исключи; остальные — проверками выше (`lsof +D`, холодность).
  Каталоги в `/tmp/claude-<uid>/`, не похожие на `<проект>/<сессия>`, — «неопознанное».
- **Установленное, не кеш** (тулчейны, версии рантаймов, браузеры Playwright) — не кандидат на `rm`;
  список и команды менеджеров — в справочнике.

Ниже таблиц, **без номеров** (их нельзя выбрать):

Правила таблицы:

- Колонка «Команда» — ровно та команда, которая будет выполнена; для команд пользователя — пометка
  «выполните вы: через `!`» или «выполните вы: в отдельном терминале» («Команды пользователю»).
- **Цифры Docker — «оценка»**: при containerd-snapshotter и общих слоях `docker system df` не
  совпадает с тем, что вернёт диск. Не складывай перекрывающиеся размеры (каталог и его подкаталог,
  образы с общими слоями) в итог — итог покажет `df` в фазе 5.
- Удаление образа — укажи цену: следующий деплой/запуск скачает или соберёт его заново.

## Фаза 4 — выполнение выбранного

Только номера, которые пользователь назвал в ответе на вопрос фазы 3. Перед первым пунктом сними
снимок инвариантов в файл:

```bash
{ docker volume ls -q | sort; echo ---; docker ps --format '{{.Names}} {{.Status}}'; echo ---; systemctl --failed --no-legend; } > W/invariants-before.txt 2>&1
```

Для **каждого** пункта, непосредственно перед командой:

1. **Повторная проверка** — те же проверки фазы 2 с теми же правилами кода возврата: объект
   существует; размер близок к табличному (`timeout 60 du -sxB1M -- <путь>`); его не держат процессы;
   для образа — тот же ID (`docker image inspect --format '{{.Id}}' <образ>`) и контейнеров от него
   по-прежнему нет; для команд с симуляцией — тот же список. Что-то изменилось или проверка не
   выполнилась — пункт **пропусти**, в отчёт — «изменился, нужно новое согласие».
2. **Проверка пути** (для файлов и каталогов): путь безопасный (см. политику); `realpath -e -- <путь>`
   совпадает с путём из таблицы; `test -L <путь>` — не символическая ссылка; путь не `/`, не `$HOME`,
   не точка монтирования (`findmnt -M <путь>` пусто). Не прошло — пункт пропустить.
3. **Команда** — ровно из колонки «Команда». Ненулевой код — пункт «упал» (с текстом ошибки),
   остальные пункты продолжай. Команды пользователя — по «Командам пользователю», с проверкой
   результата.

## Фаза 5 — сверка и отчёт

- Те же команды замера, что в фазе 0, — в `W/df-after.txt` и `W/df-i-after.txt`; **реальный
  выигрыш** — разница с `W/df-before.txt` по каждой ФС, inode — с `W/df-i-before.txt`, если проблема
  была в них. `docker system df` — отдельно («освобождено в Docker» ≠ «возвращено диску»). Выигрыш
  около нуля при удалённых объектах — ищи причину: снапшоты ФС, удалённые-но-открытые файлы. Между
  фазами 0 и 4 могло пройти время — рост логов/БД за этот срок тоже в разнице, скажи об этом.
- Инварианты — снимок заново и `diff` с `W/invariants-before.txt`: список томов не изменился (кроме
  удалённых по согласию), запущенные контейнеры по-прежнему `Up`, новых упавших сервисов нет.
  Нарушение — первым пунктом отчёта.
- Отчёт: выполненные пункты; упавшие (код, ошибка); пропущенные и почему (изменились, не прошли
  проверку пути, пользователь не выполнил или результат не подтвердился); что осталось на потом
  (например, ядро до перезагрузки).

## Ловушки

- **Работающее ядро (`uname -r`) не трогать.** Новое ядро установлено, но не загружено — старое
  удаляется только после перезагрузки (`apt autoremove --purge`), а перезагрузка — решение
  пользователя, не часть скилла.
- **Локальные бэкапы сокращать только после сверки размеров удалённой копии** (FTP/S3 листингом с
  размерами): журнал выгрузки пишет «OK», не проверяя размер, и пустой дамп тоже считается «OK».
- **`npm cache clean --force` не чистит `~/.npm/_npx`** — это отдельный кандидат.
- **Playwright (`~/.cache/ms-playwright`)** — установленные браузеры, нужные для проверки HTML
  реальным рендером; по умолчанию «не трогаю». `npx playwright uninstall` без `--all` удаляет
  браузеры **текущей** версии, а не старые.
