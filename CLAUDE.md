# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

`leonid74-ai-skills` — маркетплейс плагинов для Claude Code (`.claude-plugin/marketplace.json`).
Репозиторий не содержит приложения для сборки/тестирования в привычном смысле — это набор
декларативных артефактов плагинов (slash-команды, skills, hooks), которые Claude Code подключает
через `/plugin marketplace add`.


**Живой tmux не трогать.** Нельзя убивать или останавливать сервер tmux, в котором работает Claude:
никаких `kill-server`/`kill-session`/`kill-window`/`kill-pane`, `respawn-*`, сигналов по pid сервера —
ни самому, ни субагентам. Эксперименты с настоящим tmux — только на отдельном сервере и со снятыми
`TMUX`/`TMUX_PANE` и без конфигурации владельца: `env -u TMUX -u TMUX_PANE TMUX_TMPDIR=<каталог> tmux -L <имя> -f /dev/null …`.
Без `-f /dev/null` тестовый сервер читает `~/.tmux.conf`: continuum восстанавливает в нём сессии владельца
и через 10 минут перезаписал бы его снимок resurrect (так чуть не случилось 08.10.2026); `<каталог>` —
короткий (`mktemp -d /tmp/x.XXXXXX`), иначе путь сокета длиннее предела. Одного `-L` или
одного `TMUX_TMPDIR` мало: внутри tmux переменная `TMUX` унаследована и важнее `TMUX_TMPDIR`, так что
«голый» `tmux kill-server` в тестовом скрипте убивает живой сервер вместе с сессией Claude (так
случилось 03.10.2026). Тестовые скрипты начинать с `unset TMUX TMUX_PANE`; субагентам давать готовую
обёртку и это объяснение в брифе. Хук `guard-bash.sh` (2.19.0) блокирует только **прямые** команды остановки
(`tmux kill-*`/`respawn-*` без своего сокета `-L`/`-S`, кроме `default`; `pkill`/`killall tmux`; `systemctl … tmux`
вне чтения) — скрипт-файл он не видит, так что эта норма для тестовых скриптов остаётся.

**Опытные прогоны — под потолком памяти и времени.** Любой проверочный запуск, свой и субагента (тест,
копия блока, `awk`, свой скрипт), — в форме `( ulimit -v 1048576; timeout 120 <команда> )`.
Исключения: headless `claude -p` (опыты со скиллами) — `( ulimit -v 2097152; timeout 300 claude -p … </dev/null )`,
`node` (стенд workflow-скрипта) — `( ulimit -v 2097152; timeout 120 node … )`; полный стенд хука
`test-guard-bash.sh` (идёт ~4–5 мин) — `( ulimit -v 1048576; timeout 600 bash … )`, драйвер его мутантов — под
`ulimit -v 1048576`, `timeout 600` на каждый прогон стенда и `timeout 3600` на весь драйвер (решение владельца
30.10.2026: «если эти параметры достаточны тогда согласен, но если необходимо — их можно увеличить ещё»; до этого
стенд в Ф2a шёл с 300–600 с, драйвер — под 4 ГБ и 2400 с вне нормы). Оба рантайма резервируют
адресное пространство сверх RSS: под 1 ГБ `node` v24 падает уже на `node -e`, а `claude -p` — segfault
(пик RSS — 300–430 МБ); разведка скилла по большому файлу идёт до двух минут: 5 сбоев `claude -p` из 20
прогонов 17.10.2026, под 2 ГБ и 300 с — 0 из 16. `</dev/null` обязателен: в цикле `while read`
`claude -p` съедает stdin цикла. Файлом на
вход не давать `/dev/full`, `/dev/zero`, `/dev/urandom` и симлинки на них: чтение оттуда бесконечно;
«диск полон» имитировать только каталогом без прав на запись. Причина: Claude работает внутри tmux, и
если ядро убивает по нехватке памяти процесс в `tmux.service` с `OOMPolicy=stop` (умолчание systemd),
unit останавливается целиком — сервер tmux, все панели и Claude. Так случилось 10.10.2026:
проверочный `awk` верификатора ревью читал симлинк на `/dev/full` и занял всю память; ни одной
tmux-команды при этом не было, так что запрет «не трогай tmux» этот путь не закрывает. На этой машине
у `tmux.service` стоит drop-in `OOMPolicy=continue` (`~/.config/systemd/user/tmux.service.d/oom.conf`),
но жертву всё равно выбирает ядро, и ею может стать сам Claude, — потолок обязателен. Субагентам —
готовая обёртка и это объяснение в брифе.

## Workflow-скрипт review-code (ловушки)

- Тексты правил (ракурсы углов, skip-list, инварианты, протоколы, формат кандидата) в скрипте **не
  дублировать** — их передаёт скилл через `args` из своего `SKILL.md`. В скрипте только механика.
  Величины-зеркала `SKILL.md` — менять обе стороны синхронно: `LEVELS` («Таблица уровней»),
  `LENSES` (линзы `max`), `SECURITY_ANGLE`, `SWEEP_CAP` (фаза 2.5), `NO_SELF_SUPPRESS` (пункт 1
  skip-list), `MERGE_THRESHOLD`/`MERGE_MAX`, `DEFAULT_WAVE`/`MIN_WAVE`/`MAX_WAVE`, `MAX_PATH_LENGTH`
  и перечень корней security-категорий в `isSecurity` («Оркестрация фаз 1–2.5»), `FINDER_FIELDS`
  («Формат кандидата»), `ARGS_FIELDS` (таблица «Поле `args`»; незнакомый ключ — ошибка, №49).
- Пол finder'ов (2.21.0, решение 05.10.2026) — от поля `args.securitySurface` (триггер правила 1), **не от
  `level`**: при моратории уровень `xhigh`, а явный `max` бывает без триггера. Поле обязательное, без
  умолчания. `opusUnavailable` (только при `sessionBelowOpus: true`) переводит на `sonnet` **все** роли — повтор
  скилла по `opusSilent` (решение владельца 31.10.2026: «opus недоступен — всех на sonnet без вопросов»); строку
  «⚠️ ПОНИЖЕНИЕ МОДЕЛИ» скрипт кладёт в `notes` сам — не убирать: громкое уведомление — требование владельца.
- Рамку использования скрипт **не применяет** (решение 13.10.2026, версия 2.12.0): поле
  `args.frame` отвергается ошибкой, прогон с рамкой ведёт только режим `Agent` по тексту
  `SKILL.md`. Молча принимать поле нельзя — рамка осталась бы без исполнителя. Возвращать рамку в
  скрипт — только вместе с общим подсчётом голосов для обоих режимов и по требованиям из
  `TODO.md` (прежний код — ветка `feat/review-code-frame-workflow`): ревью нашло в нём восемь
  подтверждённых дефектов защиты подсчёта, латать их пакетом правок не стали.
- Добавочные углы `+angles` скрипт **не запускает** (версия 2.15.0): поле `args.extraAngles`
  отвергается ошибкой, лишний номер в `args.angles` — ошибкой состава углов; прогон с добавкой ведёт
  только режим `Agent`. Сессия ошибку не «исправляет» повтором без добавки — угол молча выпал бы.
  Возвращать в скрипт — только с валидацией «1…N плюс добавки» и векторами стенда (добавка внутри
  первых N, номер вне 1–9, повтор).
- Обязательные поля кандидата проверяются **после** среза по потолку, и исключение для security
  только добавляет верификацию — так признак от finder'а по-прежнему не решает, кого вытеснить. Отклонение по
  полям делает прогон `деградированный`, а локация отклонённого кандидата не считается подавленной
  по skip-list.
- Всё, что пришло от агента (путь, текст кандидата), — недоверенные данные: в текст заданий другим
  агентам только JSON-блоком, в ноты — через `showPath`; признаки от самого finder'а (security,
  категория) не должны решать, кого вытеснить из верификации. Два исключения только добавляют
  верификацию: запись `suppressed` с признаком security поднимается в кандидаты и на
  `medium`/`high`, security-кандидат без обязательных полей идёт на верификацию. Из записи
  finder'а брать только поля схемы (`CANDIDATE_FIELDS` — ключи `CANDIDATES_SCHEMA`, без ручной копии):
  служебные ключи скрипта (`promoted`, `relatedLocation`) от агента не принимаются — иначе finder
  отключит проверку или подделает отметку.
- Запуск агентов — только волнами (`runWaves`), не общим `parallel` по всему списку: волна из двух
  и более агентов без единого ответа (и волна перезапуска) трактуется как лимит использования, а не отказ
  агентов, если хоть один из них молчал, а не упал исключением (`silentWave`); хвост из одного агента нарезка (`waveBounds`) не оставляет, если предыдущая волна не меньше трёх
  (остаётся при `wave = 2` с нечётным числом заданий и у одиночного задания — sweep, одна группа).
- Оба JS-файла — в формате Prettier с дефолтами: `npx --yes prettier@3 --check <файлы>`.
- `Date.now()`, `Math.random()`, `new Date()` без аргументов в скрипте запрещены средой (ломают
  resume); промпты агентов должны быть детерминированы — иначе кэш `resumeFromRunId` не сработает.
- `meta` — чистый литерал; `meta.name` не должен совпадать с именем скилла (`review-code` занят:
  плагинные workflow и скиллы делят неймспейс `dev-toolkit:<имя>`).
- Правило, записанное в скрипте, действует **только в режиме `Workflow`**. Автономные вызовы и поиск
  на `high` и выше (пока `Workflow` сверх ориентира размера не разрешён) идут режимом `Agent`, где подсчёт голосов ведёт сессия по тексту `SKILL.md`, а
  стенд этот режим не проверяет. Каждое правило скрипта обязано быть записано и в тексте фаз; «держит
  код» в документации писать только с оговоркой о режиме. Общий счётчик голосов — в `TODO.md`.
- Режим `Agent` из `SKILL.md` не удалять — это фолбэк для автономных вызовов (у `Workflow`
  обязательный opt-in пользователя) и для сессий с малым ориентиром размера workflow.

## Архитектура: guard-bash.sh (самый сложный артефакт в репозитории)

`plugins/dev-toolkit/hooks/guard-bash.sh` — PreToolUse-хук на `Bash`: получает JSON на stdin
(`.tool_input.command`), блокирует команду с exit 2 (текст из stderr возвращается модели) или
пропускает с exit 0. Это **эвристика по тексту команды, а не реальный shell-парсинг**: лексер
`_lex` разбирает кавычки для правила `.env`, но правила `rm`, git/gh и вывода окружения режут текст
построчно `sed` и кавычек не видят (кроме белого списка простых сегментов для пути под `/tmp`); алиасы/функции и
переменные в аргументах не учитываются нигде, кроме пути под `/tmp` в правилах `rm`/`find` (присваивание в той же команде)
(зафиксировано в `TODO.md`). `.tool_input.command` не строка (массив/объект) — ошибка `jq`, то есть
блок. Любой выход, кроме 0 и 2
(падение под `set -euo pipefail`), `trap EXIT` превращает в блокировку — код 1 Claude Code считает
неблокирующей ошибкой и выполнил бы команду. `printf … | grep -q` не использовать: под `pipefail`
ранний выход `grep -q` даёт SIGPIPE, и условие становится ложным — только here-string `<<<`.

Составные команды (`&&`, `||`, `;`, `|`) разбираются на под-сегменты *до* применения правил —
иначе `/tmp`-исключение для `rm` ломается на цепочках вида `mkdir -p /tmp/x && rm -rf /tmp/x`
(проверка всей строки целиком блокировала бы безопасный кейс).

**Исключения «текст, а не команда» даёт только шаблон сообщений (`_tpl_try`)**, не лексер. Команда-
сообщение — `git [-c user.name=|-c user.email=|-C <путь>] commit <флаги> -m "…"`/`-F <путь>`/`-F -`,
`gh pr|issue create|edit|comment|merge [N] <флаги> --title/--body "…"`/`--body-file`, одиночный
`echo`/`printf`; у git/gh допустим редирект вывода `N>&M` и `>`/`>>`/`N>` в файл (оператор — токеном целиком, не
подстрокой текста; цель — путь, её судит правило `.env`; в форме C — только до `-m`); литерал `__CSUB__` (внутренняя
метка формы C) в команде отключает шаблон; с here-doc — `-F -`/`--body-file -` `<<'EOF'` в конце строки и `-m "$(cat <<'EOF'` …
`EOF` / `)"`. Она ищется в цепочке: **префикс** до неё проходит простой сканер кавычек (на `$(`, `` ` ``,
`<<`, скобках, `{`, комментарии поиск прекращается), **хвост** после разделителя `;`/`&&`/`||`/перевода
строки дописывается как есть (в нём ищется следующая команда-сообщение), конвейер `|` сразу после неё —
не шаблон (`git commit -m ".env" | xargs cat`). Текст сообщения (без `$`/`` ` ``/`\`) заменяется на
`MSG`, тело here-doc отбрасывается; префикс, пути, флаги и хвост остаются в `_scmd`, её судят все
правила (секреты — исходную строку). Всё, что не подошло, проверяется целиком, тела here-doc — как
строки команд. **Не возвращать решение «данные/код» лексеру**: первая версия 2.3.1
так делала, и два прохода ревью нашли десять расхождений лексера с bash (`${x:-<<EOF}`, `<<<` в
`$( )`, `$'EOF'`, `#` в `$( )`, CRLF, `EOF)`, `$(` после разделителя, конвейер в теле, `2>` как вывод
в файл, `coproc`) — каждое прятало настоящие команды за «данными». Расширять грамматику шаблона —
только с тест-векторами на границы и мутационной проверкой. **Бюджет шаблона** — команды до 16 КБ и
не более 8 вызовов `_tpl_try` (`_tpl_budget`): рекурсия по цепочке без потолка давала кубическое время
(632 × `git commit -m "x" &&` — 614 с, за таймаутом, а при таймауте хук команду не блокирует); сверх
бюджета остаток проверяется целиком. Пороги длины — в байтах (`_bytes`, `LC_ALL=C`): `${#…}` в UTF-8 считает
символы. Команда длиннее `_LX_MAX` (32 КБ)
лексером не разбирается — `.env` ищется грубо по всей строке. Разбор идёт по байтам под `LC_ALL=C`
и кусками (`sed` + `mapfile`), не
`${s:i:1}`: подстрока в bash — O(длины строки), посимвольный обход был квадратичным и выводил хук

каждый токен не ставить — `setlocale` на входе/выходе стоит секунды.

Детект рекурсивного `rm` токенизирует сегмент по словам (как и правило `.env` — по токенам
лексера; остальные правила — однострочный `grep -E`), потому что GNU `rm` пропускает флаги через
getopt-permutation: recursive-флаг может стоять и после операнда (`rm /home/x -r`). Команда внутри
сегмента ищется равенством токена (`rm`/`*/rm`), не вырезанием текста до последнего слова "rm" —
иначе слово "rm" внутри имени операнда (`rm -rf /home/rm-backup`) обрезает разбор раньше настоящих
флагов и глушит детект. Lowercase токена (`${_tok,,}`) используется только для регистронезависимого
опознания команды/флагов — сравнение операнда с `/tmp` идёт по исходному регистру, потому что `/tmp`
на Linux регистрочувствителен (`/TMP` ≠ `/tmp`). `set -f`/`set +f` вокруг токенизации отключает
pathname expansion — без него `rm -rf /tmp/*` раскрылся бы в реальные файлы `/tmp` на машине, где
запущен хук, а не остался текстовым паттерном.

**Путь под `/tmp` (2.17.0) — вывод только в префиксе из простых сегментов, после первого непростого — сброс**
(`_rm_cplx`, `_rm_spoil`, `_rm_track`, `_rm_tmp`): 239 из 270 блоков `rm -r` в транскриптах владельца были удалением
внутри `/tmp` — переменной из той же команды, каталогом `mktemp`, относительным путём после `cd`; ложный блок толкал
агента на неохраняемые пути (скрипт-файл, `find -delete`). Простой сегмент задан **белым списком** — и по тексту, и по
команде. Текст (`_rm_cplx`): после снятия закрытых `'…'`/`"…"` — только безопасный алфавит, `$ИМЯ`/`${ИМЯ}`,
редиректы; нет `$'`/`$"`, `<<`, `[[`, `IFS` (где угодно), ключевого слова первым, сегмента > 4 КБ. Команда
(`_rm_spoil`) — тоже **положительным списком**: первое слово после присваиваний ровно `cd`, `set` с флагами, `rm`,
`find`, `mkdir`, `ls`, `echo`, `which`, `head`, `grep`, `cat`, `tail` (сверено с префиксами истории), присваивание с
индексом `X[…]=` — сброс. **Перечень «опасных» команд вместо списка не возвращать**: два ревью 2.17.0 нашли в перечнях
слов-аргументов и встроенных команд 13 пропусков — функции снимка оболочки (`nvm_cd`), имя вплотную к редиректу, маска
первым словом; `find` и `grep` в оболочке Claude Code — функции, но только с `local` и подоболочкой. Управляющий байт
(кроме `\t`, `\n`) в команде — сброс с начала. С первого непростого сегмента (и в команде
> 8 КБ, и в команде без букв `rm`/`find`) переменные и `cd` не в счёт до конца команды — только литерал, как в 2.16.0:
**не «замораживать» состояние** — после непонятой формы `rm` может исполнять другой процесс (тело here-doc,
`bash -c '…'` с `;` внутри, `ssh host '…'`: там `$S` пуста, выйдет `/*`). Перечень признаков «сложной формы» вместо
белого списка **не возвращать**: три плана на нём (П2, 28.10.2026) дали по классу пропусков `/*` каждый. Белый список
ошибался трижды (`<<`, `${U`, `$'a\'`) — расширять алфавит или список команд только с вектором, мутантом и прогоном
истории. В префиксе: переменная — `t`, только если каждое её присваивание — путь под `/tmp` не после `&&` и не в
конвейере (спецпеременные bash — `_`, `PWD`, `REPLY` … — и readonly `UID`, `PPID` … — никогда); `$(mktemp …)` с
парными кавычками и аргументами `-d -q -t` и шаблоном под `/tmp` или с `-t` — `u`, годится только голой `$D` (шаблон
без пути и без `-t` — каталог в текущем, `x`); `'$S'` — не переменная; подстановка в хвосте (`$S/$R`) — вне
`/tmp`; `cd` на абсолютный путь или переменную под `/tmp` действует, пока до удаления одни `&&` (`;` после неудачного
`cd` оставил бы `rm` в проекте); `&&`/`||`/`|` в конце строки — сброс. Вид разделителя — массив `_segsep` (метки
`\x1c`–`\x1e` того же `sed`, затем сведены в `\x1f`: нарезка прежняя). `..` — вне `/tmp`: сегмент `..` (и с приклеенным
редиректом — `<`, `>`, `&` считаются разделителями), литерал `/tmp/…` с `$` (кроме `$$`), `{` или `` ` ``, компонент
пути на `.` с маской (`_rm_dm`: `.[`, `.?`, `.*`, `..*` — без `globskipdots` совпадает с `..`); слово с `\` — вне
`/tmp`. Редирект в `/dev/null` и `N>&M` — не операнд (иная цель судится как путь); `>`/`<` вплотную к имени
(`rm>f`, `find>f`) — не часть имени. Правило `find` (`_find_del`): `-delete` (и в кавычках) или `rm` в команде
`-exec` (и за обёрткой — `sudo rm`, `env rm`) судят пути `find`. Пути первого `find` — **каждое голое слово вызова**,
кроме аргумента предиката (таблица `_fd_arg`), редиректа и слов команды `-exec`: `bfs`, которым `find` подменён в
оболочке Claude Code, принимает путь в любом месте выражения, после `-f` и после конца `-exec` на `+` (хвост после
`\;` — другой сегмент нарезки, не судится: `TODO.md`); `{}` первого `find` — путь; `-files0-from` — блок. Вложенный
`find` (после `-exec`) судится лишь частично (`TODO.md`); `-name find` — аргумент. `rm` после `-exec` судит правило `rm`: `{}` и `'{}'` — не путь, конец `-exec` — `\`, `'`, `"` (после
нарезки по `;`) только последним словом, `+` — только сразу после `{}`. Кавычки снимаются с имени и флагов `rm`,
только если они парные и стоят целым словом (`'rm'`, `"-rf"`) первым словом команды: иначе `grep "rm -rf" f` стал бы
командой; за обёрткой (`sudo \rm`) — пропуск, как в 2.16.0; конец опций — только `--` целым словом (и `'--'`, `"--"`), иное слово из `-`, кавычек и `\`, где есть кавычка или `\`
(`\-\-`), — операнд вне `/tmp`; `r""m` —
принятое ограничение (предфильтр по слову `rm`; так пишут тест-векторы в here-doc). Новую форму — только с прогоном корпуса истории
(старый и новый хук, разбор каждого расхождения) и защитными векторами (переприсвоение, `;`, `..`, подоболочка).

**Нарезка на команды (2.16.0) — одна для правил `rm`, барьера, вывода окружения и git** (`_segtext`): один `sed`
режет по `&& || ; |` в `\x1f`, перевод строки остаётся строкой, `\⏎` склеен пробелом; одиночный `&` **не режет**: нарезка не
видит кавычек, и `&` в `--format="%h & %s"` или `X="a&b" printenv` оторвал бы флаг от команды (так было в первой
редакции 2.16.0 — ревью); байты `\x1c`–`\x1f` в команде заранее заменяются буквой (иначе подделал бы метку); захват —
присваиванием `$( )` под `set -e`: сбой `sed` — блок, не пустой разбор.

Правила git о потере работы, истории и remote (2.16.0) — **по отдельной команде, а не по всей строке**, в два слоя
(решение владельца по ревью `xhigh`: не усложнять). Сегмент со словом `git` и незакрытыми кавычками или скобками
(или с `\` перед разделителем, или с незакрытой `{`) склеивается со следующими **в той же строке** (`git push "a;b"
--force`, `-c x=a\;b`, `${U:-a;b}`; через перевод строки — нет, иначе апостроф
в прозе here-doc тянул флаг соседней строки). (1) **Сетка** — прежние три регекса `reset --hard`/`push --force`/
`branch -D` по тексту каждой склеенной команды: она и есть основная защита этих форм и без отдельного кода ловит
для них обходы разбора по словам (`feat/git-x --force`, `--hard>/dev/null`, `$(true)git`, `git.exe`, `${GIT:-git}`,
алиас в `-c`, редирект до подкоманды); новые формы (`$(true)git clean -f`) сетка не видит. Цена — ложный блок текста внутри одной команды, как в 2.15 (`git log --grep='reset
--hard'`). (2) **Разбор по словам** — новые формы (`clean -f`, `checkout -f`, `+ветка`, адрес вместо remote, `-c
alias.`/`remote.`/`url.`/`branch.` …): слова голым word-splitting, слово `git`/`*/git`/`git.exe` — начало команды,
`git-<подкоманда>` — только первым словом сегмента, «голое» `git` — конец предыдущей; глобальные опции и редирект до
подкоманды пропускаются; long-опции — по префиксу ≥ 3, короткие — кластером через `${x%%[vreq]*}` (не посимвольно).
Сверх бюджета `_gbud` (20 000 слов) или в команде со словом `git` (с 2.18.0 — и `gh`) длиннее 16 КБ — **блок** «разбейте команду»: не
пропуск (длинный хвост увёл бы новые формы из-под разбора) и не выход за таймаут (команда не блокируется); в
транскриптах владельца таких команд нет. Блок идёт под `LC_ALL=C`: замены и
срезы в UTF-8 на длинном слове стоят секунды (`${s//\"/}` на 48 КБ: 1,2 с против 40 мс), `${t##*/}` квадратичен и в
C — опознание по суффиксу (`== */git`). **Набор правил сверен с корпусом команд транскриптов владельца** (27.10.2026):
блок только для форм, которые в работе не исполнялись; откат всего дерева (`checkout -- .`, `restore .`),
`worktree remove --force`, `--no-verify`, `push origin :<ветка>` — свободны по решению владельца. Новое правило git
добавлять с прогоном того же корпуса (старый и новый хук, разбор каждого расхождения на «команда» и «текст») и с
приёмочными векторами обходов в стенде: кавычки не учитываются, и каждое правило блокирует и упоминание формы в
тексте. Подкоманда `rm` после `git` — не команда `rm`, только если `git` (ровно) — первое слово сегмента и в нём нет
подстановки (`sudo -u git rm -r`, `git rm "$(rm -r …)"` — правило `rm` судит).

Правила секретов ловят **значения**, а не слова: известные форматы ключей (регистрозависимо,
`LC_ALL=C`, с границей слева — иначе `task-…` совпадёт с `sk-…`) и присваивание литерала ≥ 8
ASCII-символов имени `password`/`secret`/`token`/`api_key` (литерал с `$`, `/`, `~`, `.` в начале —
ссылка/путь, пропускается). Не возвращать правило «слово в любом месте команды» — оно блокировало
имена классов/тестов и не ловило ключей. Правило `.env` — **fail-closed по сегменту** (allowlist
`ls`/`stat`/`test`/`[`/`[[`/`git status`/`git check-ignore`), а не список «читающих» утилит: перечислить
всех читателей невозможно. Токен сверяется после снятия кавычек и `\` **по правилам bash**
(`_env_unquote`: в `"…"` `\` остаётся перед обычным символом — `grep "\.env"` это регулярка, а не
путь; `$'…'` раскрывается через `${x@E}`), с glob-хвостом (`.env*`, `.env{,}`, `.env~`),
присваиваниями (`f=.env`) и слитным значением короткой опции (`-F.env`). Цель редиректа — всегда
путь и блокирует даже allowlist (`ls > .env`, `git check-ignore --stdin < .env`); allowlist git — только
`status`/`check-ignore` **сразу** после `git` (`git -c core.fsmonitor=… status` исполняет конфиг).
Упоминание `.env` в тексте сообщения до правила не доходит — его заменил шаблон (см. выше); флаги
шаблона сверяются **точно и с учётом регистра** (`-Fm` — это `-F m`, у gh `-T` — шаблон-файл, `-c`
у git — только `user.name`/`user.email`: прочие ключи исполняют код). Подстановка `$(`/`` ` ``/`<(`
(в том числе `$\⏎(`) в сегменте блокирует `.env` даже у
allowlist-команды (`ls $(cat .env)`). Неполный glob (`.en?`) и путь через переменную/файл-посредник
текстом не различимы — принятое ограничение, закрывает sandbox ОС. Фейковые токены в тест-векторах — только конкатенацией (`"gh""p_…"`):
иначе хук заблокирует запуск теста, а сканер секретов в CI примет фикстуру за ключ. Новые ассерты
проверять мутацией (`GUARD_BASH_HOOK=<копия хука>` подменяет проверяемый файл).

значение — `\$`, `${#…}`, `${…:+…}`/`${…+…}`) — блок; одиночный `echo "$X"` шаблон сообщений превращал в `echo MSG`
(`_tpl_var` пускает `$ИМЯ`), поэтому шаблон **отказывает** на ссылке на секретную переменную (сужение грамматики
шаблона); куски `'…'` слова перед этим снимаются **по грамматике слова шаблона** (`sed -z`: `"…"` целиком, апостроф в
нём — литерал; наивная замена `'…'` съела бы ссылку между апострофом в `"…"` и поздней `'`); в правиле окружения —
так же (`"…"` с `\"` внутри — целиком): `echo 'export T=$T' | tee f` — не вывод значения. `_sec_ref` — один разбор
по `$` (`IFS=$`) с предфильтром по корню имени: срез остатка за каждым `$` был квадратичен. Правило вывода окружения:
имена команд — с учётом регистра (`ENV` в шаблоне — не команда), кавычки с имени снимаются; сегмент, **начатый внутри
кавычек строки** (`_qscan`, ревью PR #90), — текст, не команда. `_qscan` — **автомат кавычек bash** по токенам одного
`sed` (в `'…'` закрывает только `'`, в `"…"` — только `"`, `\` вне `'…'` экранирует): счёт чётности ошибался на
апострофе в `"don't"`. Кавычка, открытая **строкой оболочки** (`sh`/`bash … -c`, `ssh <хост>`, `eval`), — команды;
одиночный `&` вне кавычек — граница команды; строка, где кавычка не закрылась (продолжение многострочной строки,
апостроф прозы here-doc), и строка > 8 КБ — без пропуска. **Состояние кавычек между строками не переносить**: проза
here-doc с апострофом спрятала бы команды после `EOF`. **Склейку сегментов по кавычкам для правил окружения и tmux не
использовать**: склейка прячет хвост строки, на прототипе она слила шаблон regex в «команду» (ложный блок рабочей
команды корпуса). Отличие допустимого: у `echo`/`printf`/`printenv` ссылка на секрет ищется и в следующих сегментах,
начатых внутри кавычек (`echo "x; $T"`) — это только прибавляет блоки, а те сегменты судятся и сами. Вложенный `claude`:
подстрока `dangerously-skip-permissions`/`bypasspermissions` (без буквы перед ней) **и** слово `claude` где угодно в
`_code` — блок; флаг после `;` внутри промпта и режим в строке `--settings` тоже видны; флаги опытов свободны. tmux
(`_ks_scan`, один проход по словам с состоянием): подкоманда `kill-*`/`respawn-*`/`killp`/`killw`/`respawnp`/`respawnw`
**на позиции подкоманды** (после глобальных опций и после `\;`; у подкоманд, исполняющих аргумент, — `send-keys`, `if-shell`,
`confirm-before`, `run-shell`, `bind-key`, `command-prompt`, `display-menu` — и в аргументах; слово `tmux` в аргументе
(`split-window 'tmux …'`) — вложенный вызов, его свой сокет не переходит на внешнюю цепочку после `\;`) без своего сокета —
глобальной `-L`/`-S` **до первой подкоманды** (`select-pane -L` — «влево»; значение `default`/`…/default` своим не
считается — решение владельца 30.10); слово `…/tmux` внутри вызова tmux — аргумент; `pkill`/`killall` с **любым**
аргументом-не-опцией `tmux` (`-S<сигнал>` — опция, свой сокет — только в шаблоне после `tmux`), `systemctl` — **белый
список** глаголов чтения; слово в кавычках или `` `…` `` — текст (кроме строки оболочки: после имени оболочки и опции с
`c`, после `eval`); имя команды — сравнением по суффиксу (`== */tmux`); склейка только по `\` в конце сегмента

## Синхронизация vendor-копии chat-handoff

`plugins/chat-handoff/skills/chat-handoff/SKILL.md` — vendor-копия из
[Leonid74/ai-skill-chat-handoff](https://github.com/Leonid74/ai-skill-chat-handoff), не редактируется
напрямую. При обновлении upstream:

```bash
curl -fsSL https://raw.githubusercontent.com/Leonid74/ai-skill-chat-handoff/main/SKILL.md \
  -o plugins/chat-handoff/skills/chat-handoff/SKILL.md
```

Если в upstream поднялась версия (frontmatter `version:` в `SKILL.md`), синхронно поднять `version`
в `plugins/chat-handoff/.claude-plugin/plugin.json` — иначе пользователи не получат обновление
(Claude Code обновляет плагин только при изменении поля `version`).

## Версионирование плагинов

Версия каждого плагина живёт в его `.claude-plugin/plugin.json` (поле `version`). Обновление до
пользователей доходит только при изменении этого поля — бамп версии обязателен при любом
пользователь-видимом изменении плагина (новое правило хука, новый skill/команда, фикс поведения).
